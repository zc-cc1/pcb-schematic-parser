## 1. 先分清四样东西

- Visual Studio是开发环境；安装它不等于已装C++编译器。Visual Studio Code则是编辑器，也不自带完整C++工具链。
- MSVC把C++代码编译成目标文件，链接器把程序和库连接起来。
- CMake读取CMakeLists.txt并生成构建工程，本身不是编译器。
- OpenCV C++ SDK提供头文件、链接库和运行库。`pip install opencv-python`提供Python绑定，不能代替本课程的C++ SDK。

本机检查发现Visual Studio Community 2026安装记录，但未找到其MSVC工具目录和内置CMake；常见位置也未发现OpenCV C++ SDK。以下是准备步骤，不表示已替你安装或已编译成功。

## 2. 准备Windows工具链

打开Visual Studio Installer，修改安装，选择“使用C++的桌面开发”，确认包括MSVC x64/x86构建工具、Windows SDK与C++ CMake工具。完成后打开对应Visual Studio的Developer PowerShell，使用x64目标环境。

```powershell
cl
cmake --version
cmake --help
```

`cl`显示编译器版本且提示缺少源文件，是工具已可访问的信号。若找不到cmake，可使用安装目录下cmake.exe的完整路径或安装CMake并加入PATH。不要把“命令未加入PATH”直接当成“软件未安装”。

从[OpenCV官方发布](https://github.com/opencv/opencv/releases)获取适用于Windows/MSVC的4.x开发包，解压到如 `C:/libs/opencv`。确保程序、编译器、SDK架构一致（本课采用x64）。不要把MSVC预编译的.lib直接交给MinGW使用。实际包与所用工具集必须兼容；若不兼容，使用对应工具集或重新编译OpenCV。

找出真正包含OpenCVConfig.cmake的目录：

```powershell
Get-ChildItem 'C:/libs/opencv' -Filter OpenCVConfig.cmake -Recurse
Get-ChildItem 'C:/libs/opencv' -Filter 'opencv*.dll' -Recurse
```

路径只是示例，替换成自己的解压目录。`OpenCV_DIR`应指向包含配置文件的目录，不是include目录，不是某个DLL文件。

## 3. 先编译不依赖OpenCV的程序

在Developer PowerShell中进入本周目录：

```powershell
Set-Location 'C:/Users/zc/Desktop/vision/opencv/OpenCV学习路线/01_cpp_basics'
cmake -S . -B build_basics -DWEEK01_WITH_OPENCV=OFF
cmake --build build_basics --config Release
ctest --test-dir build_basics -C Release --output-on-failure
```

CMake会选择可用的默认生成器；若不能找到Visual Studio，检查 `cmake --help` 列出的生成器，与实际安装版本对应后用 `-G` 显式指定。Visual Studio生成器采用x64时可加 `-A x64`；Ninja不使用这个参数，应从x64开发终端配置。换生成器时用新的build目录，不复用旧缓存。

Visual Studio多配置构建通常生成 `build_basics/Release/basics.exe`；Ninja单配置构建通常是 `build_basics/basics.exe`。可用以下命令找到并运行：

```powershell
$basicsExe = Get-ChildItem './build_basics' -Filter basics.exe -Recurse | Select-Object -First 1
& $basicsExe.FullName
```

预期包含value=20、value=30、add(3,5)=8、int sum=260、narrowed=4。

## 4. 编译OpenCV主例与练习

假设 `C:/libs/opencv/build` 中有OpenCVConfig.cmake；若实际位置不同，必须替换：

```powershell
cmake -S . -B build_opencv -DWEEK01_WITH_OPENCV=ON -DOpenCV_DIR='C:/libs/opencv/build'
cmake --build build_opencv --config Release
```

在**当前终端**加入与链接库匹配的DLL目录。下面以常见结构示意，vcXX必须换成实际目录名，且Release不能随意配Debug版DLL：

```powershell
$opencvBin = 'C:/libs/opencv/build/x64/vcXX/bin'
$env:PATH = "$opencvBin;$env:PATH"
ctest --test-dir build_opencv -C Release --output-on-failure
```

CTest调用basics、demo、exercise_solution共3个程序，使用各自返回码判断是否通过。要直接看demo的终端输出：

```powershell
$demoExe = Get-ChildItem './build_opencv' -Filter demo.exe -Recurse | Select-Object -First 1
& $demoExe.FullName
$exerciseExe = Get-ChildItem './build_opencv' -Filter exercise_solution.exe -Recurse | Select-Object -First 1
& $exerciseExe.FullName
```

复制或移动课程后应重新运行CMake配置，因为输出目录是在配置时写入程序的。修改.cpp后必须重新构建，再运行exe；旧exe不会自动跟随源码变化。

## 6. 根据报错判断处在哪一层

| 报错 | 说明 | 优先检查 |
| --- | --- | --- |
| 找不到cmake/cl | 工具不可访问 | 工作负载、开发终端、PATH |
| 找不到OpenCVConfig.cmake | 配置阶段找不到SDK | OpenCV_DIR与包内容 |
| 找不到opencv2/core.hpp | 编译阶段头文件路径错误 | include配置、SDK完整性 |
| unresolved external/LNK错误 | 链接阶段缺库或不兼容 | x64、编译工具集、库与构建配置 |
| 缺少opencv_world...dll | 运行时找不到动态库 | 当前终端PATH中的实际bin目录 |
| PNG写入失败 | 输出编码或文件操作失败 | 目录权限、SDK的PNG支持、磁盘空间 |

接口参考：[cv::Mat](https://docs.opencv.org/4.x/d3/d63/classcv_1_1Mat.html)、[OpenCV与CMake](https://docs.opencv.org/4.x/db/df5/tutorial_linux_gcc_cmake.html)。后者展示跨平台构建基本模式，Windows工具选择按本页说明。
