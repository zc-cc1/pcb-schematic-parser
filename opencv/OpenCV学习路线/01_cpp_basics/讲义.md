## 1. 从.cpp到.exe：先知道代码怎样开始工作

C++源码像菜谱，编译器把它变成机器能执行的指令，链接器补上程序用到的库，最后形成可执行文件。`#include`告诉编译器去读函数和类型的声明，并不等于已经完成链接。

`#include <iostream>`引入标准输入输出工具，`std::cout`用于打印。`#include <opencv2/core.hpp>`引入OpenCV核心类型；真正用到的实现还要由CMake链接相应库。`std::`和`cv::`像不同工具箱的标签，避免同名工具混淆。

```cpp
#include <iostream>
int main() {
    std::cout << "Hello OpenCV\n";
    return 0;
}
```

main是程序入口。大括号围住一段代码；多数语句末尾用分号。`<<`在这里把内容送到输出流，`\n`换行。return 0通常表示正常结束，非零值表示失败。这也是本课CTest判断结果的依据。

## 2. 本周需要的C++语法，先学够用的部分

`int width=300;`创建一个整数变量；`const int height=180;`表示height后面不能重新赋值。`int values[]={10,20,30};`是一组连续存放的整数，编号为0、1、2。不要访问values[3]，它已经越界；C++原生数组不会替你可靠地拦住这种错误。

```cpp
for (int i=0; i<3; ++i) {
    if (values[i]>15) {
        std::cout << values[i] << '\n';
    }
}
```

循环先令i=0，每轮开始检查i<3，执行后把i加1。因为只有20、30大于15，打印两行。`=`是赋值，`==`是比较相等，不要混用。`%`是求余，后面用它交替画黑白格。

```cpp
int add(int a, int b) {
    return a+b;
}
```

函数像小机器：输入两个int，交还一个int。`add(3,5)`得到8。先运行[basics.cpp](basics.cpp)，亲手改变条件和数字，预测再核对。暂时不需要学习继承、模板元编程或手动new/delete。

## 3. 图像不是电脑眼中的“风景”，而是一张数表

灰度图每个位置有一个亮度数，8位无符号类型能表示0～255；彩色BGR图每个位置放三个数，依次表示蓝、绿、红。纯蓝是(255,0,0)，纯绿是(0,255,0)，纯红是(0,0,255)。

```cpp
cv::Mat image(180, 300, CV_8UC3, cv::Scalar(40,40,40));
```

Mat负责组织像素数据。180是行数，也就是高度；300是列数，也就是宽度。`CV_8UC3`拆成8位、Unsigned无符号、Channels为3。`Scalar(40,40,40)`给每个位置相同初始颜色，所以得到深灰色画布。

`image.rows`为180，`image.cols`为300，`image.channels()`为3。`image.type()`是编码后的类型编号，不要把它当作通道数；`image.empty()`可用于检查是否没有有效数据。

## 4. 为什么坐标(x,y)访问时变成(y,x)

想象表格：先找到第几行，再找到该行第几列。图像x向右、y向下，所以数组式访问先y后x。点(30,50)要写：

```cpp
cv::Vec3b pixel = image.at<cv::Vec3b>(50,30);
int blue = pixel[0];
```

`Vec3b`是一组3个8位无符号数，适合本例CV_8UC3图像。`at<T>`里的T要与像素类型匹配：灰度CV_8UC1用 `at<unsigned char>`，不能不加判断地套Vec3b。

若想修改原图，可直接写 `image.at<cv::Vec3b>(50,30)=cv::Vec3b(255,0,0);`。或者使用引用：

```cpp
cv::Vec3b& target = image.at<cv::Vec3b>(50,30);
target[0] = 255;
```

`&`在声明中表示引用，相当于给原来的像素起别名。若写成不带&的 `cv::Vec3b target=...`，得到的是这个小像素值的副本，改target不会改原像素。这里别把“像素值复制”和下一节“Mat共享数据”混为一谈。

## 5. ROI是一扇窗，clone是一份复印件

```cpp
cv::Rect region(20,40,70,100);
cv::Mat roi = image(region);
roi.setTo(cv::Scalar(255,0,0));
```

Rect参数是x、y、宽、高，不是两个角点。本例覆盖x=20～89、y=40～139，右边界与下边界不包含在内。区域必须完全在图像范围内；负坐标或越界宽高可能触发异常。

roi通常与image共享像素，好比透过窗口涂原画。`cv::Mat shared=image;`也只复制管理信息，共享底层像素，称浅拷贝。`cv::Mat copied=image.clone();`才复制像素，称深拷贝。

主例先clone一张copied，再让view指向copied左上角，修改view后copied变白、image不变。画关系图：`image←shared`共享一组数据，`copied←view`共享另一组数据。Mat会管理常规引用计数，本周无需手动释放像素内存。

## 6. 250+10究竟等于多少：C++不能照抄NumPy解释

```cpp
std::uint8_t a=250, b=10;
int sum = a+b;                                      // 260
auto small = static_cast<std::uint8_t>(sum);         // 4
auto safe = cv::saturate_cast<unsigned char>(sum);   // 255
```

第一行的类型只能存0～255，但相加前C++会做整数提升：这里用int算出260。只有把260转回8位无符号时才按256取模成为4。不能写成“C++的uint8_t相加直接等于4”。

图像增亮往往希望超过255就停在255，低于0就停在0，这叫饱和裁剪。saturate_cast完成这种转换。本周delta为60或-50，先用int计算，避免亮处变黑、黑处减亮后反而变亮。

unsigned char或uint8_t直接送入cout时可能被当成字符显示，因此打印时转成int。`static_cast<int>(small)`只改变显示所用类型，不会把已经变成4的值恢复成260。

## 7. 安全增亮函数怎么读

[image_utils.hpp](image_utils.hpp)中的brighten先检查输入是CV_8UC3，再clone结果图，用y、x、通道c三层循环处理像素。读取pixel作为值副本，用target引用指向输出像素，每个通道都做饱和转换。

签名 `const cv::Mat& image`表示按引用接收输入、在该函数中不修改输入；返回 `cv::Mat`交还结果。这里不深入讨论Mat共享数据下的所有const细节，只要求函数遵守“不修改传入图像”的设计。

双重/三重循环适合教学，生产代码可以使用OpenCV的批量算子。例如本例uint8增亮可用 `image.convertTo(result,-1,1.0,60.0)`；不要贸然用convertScaleAbs代替任意减亮，它会取绝对值，和“负数截成0”含义不同。

## 9. 棋盘练习：先口算再编程

160×240画布，每格40×40，共4行6列24格；一半白色，即12格，白像素12×40×40=19200。判断 `(row+col)%2==0` 时画白，其他保持黑。注意这里row/col是“格子编号”，需要乘40才变成像素坐标。

减亮50后，白色255→205，黑色0→0。如果黑格变成206，说明你做了普通无符号缩窄，而没有饱和裁剪。这个可预测的错误很适合检验自己是否理解数值类型。
