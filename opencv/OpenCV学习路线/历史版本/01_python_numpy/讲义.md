学习方法：先读直觉和小例子，再看代码；不懂时停下来运行、打印中间值。理解的标准是能预测变化并解释结果，而不是一次读完。


## 1. 先把图像想成一张数字表

黑白照片并不是电脑眼里的“人”和“树”，而是一张数字表。这里的灰度图每个格子存一个0～255的整数：0表示黑，255表示白，中间表示不同亮度。彩色图在每个格子放三个数，分别控制蓝、绿、红。算法先处理数字，处理后的数字才由屏幕显示成画面。

`shape=(180, 300, 3)` 表示180行、300列、每格3个数，因此图片高180、宽300。数组从0开始编号，最下面一行是179，最右面一列是299。把这句话说顺，比背十个函数更重要。

## 2. 读代码需要的 Python，先学这些

```python
brightness = 60             # 给数字起名字；=表示赋值
colors = [10, 20, 30]       # 列表：按顺序收纳几个值
for value in colors:        # 依次让value等于10、20、30
    if value > 15:          # 条件成立才执行缩进的内容
        print(value)       # 因而只打印20、30

def add(a, b):              # 给一段可重复的计算起名字
    return a + b            # 将计算结果交还给调用者

result = add(3, 5)          # result等于8
```

缩进是语法，统一用4个空格。`range(3)` 给出0、1、2，不包括3；`enumerate(colors)` 同时给出编号和对应元素。`(180,300,3)` 是元组，可以理解成不打算修改的一组尺寸。`{'count':3}` 是字典，用名称取值：`data['count']` 得到3。后面保存的 JSON 文件，就是这种有名称的数据记录。

`import numpy as np` 是导入工具并起短名字；`np.zeros(...)` 是使用工具中的函数。`if __name__ == '__main__':` 表示直接运行这个文件时才调用下面的 `main()`；练习答案导入 demo 中的工具时，不会顺便执行整个演示。

## 3. 两套坐标为什么看起来颠倒

数学里写点的位置习惯用 `(x,y)`，x向右、y向下。数组按“先找哪一行，再找哪一列”访问，所以写 `image[y,x]`。例如x=30、y=50处的蓝色像素，要读 `image[50,30]`。

```python
image = np.zeros((180, 300, 3), dtype=np.uint8)
image[40:140, 20:90] = (255, 0, 0)
```

第一句创建黑色画布。第二句选择第40～139行、第20～89列，染成蓝色。冒号表示范围，左闭右开，区域高 `140-40=100`、宽 `90-20=70`。右边一个颜色能填满整片区域，是 NumPy 的广播机制：把同一个值应用到许多格子。

## 4. 为什么250加10竟然等于4

`uint8` 意思是无符号8位整数，只装得下0～255。把它想成只有256格的计数器，超出后绕回开头：260减去256等于4。图片直接做这种加法，亮处可能反而变暗。

本周 `brighten` 的三步是：先用 `astype(np.int16)` 换一个更大的容器；加亮度后用 `np.clip(...,0,255)` 把越界数拉回范围；最后再转回 uint8。`clip` 不是除法，也不是按最大值缩放，260就变成255，负数就变成0。

## 5. 为什么改局部会连原图一起变

`roi = image[40:140,20:90]` 通常得到原图的一扇“窗口”，两者共享数据。对 roi 赋值，原图也会改变。`roi = image[40:140,20:90].copy()` 则是把这一块复印出来，后续互不影响。故意运行 `04_view_changed_parent.png` 的代码，观察左上角变白，就是理解这件事最快的办法。
