# 数字引脚字段二次 OCR 恢复

`agent.finalize_pin_field_recovery` 在 target 格式的现有引脚位置校正和电源导线导出之后运行。输入仅为当前图的原图、候选、元件记录与图结构；不读取标注，不包含图号、指定元件或预期引脚编号。

自动选择已有几何候选中的缺编号引脚、同名多号库映射歧义，以及竖向连接器的裸数字名称缺失。合并明确指向主候选的文字辅助候选，竖向共线无名重复点保留外侧主点。跨归属、字段冲突、重复编号不合并。

先对选中元件裁剪做 1×/3×、0°/90° OCR；编号列与行偏移由已观测文字估计。水平数字从中性深色字形分离红绿引线，并去除长水平干扰线后做 3×/5×单字识别；竖向数字使用局部双方向 OCR。至少两个置信度 >=0.98 的视图才采信；6/9 冲突只在同器件既有编号提供明确方向证据时复核。多倍率并非统计独立证据。

只对有几何候选、已有可靠归属的字段补全，不补检测点或猜编号顺序。库映射重新分配必须是完整的一对一事务，且两脚已附着于同一已导出网络，否则整对保留原值。已有名称、引脚键不会因补全被删除。

网络成员仅同步到有当前图候选附件证据的已导出网络；坐标和 network_id 必须匹配，已有成员不重复连接另一网络。不新增网络、导线或推测连接。原图无印刷编号、未知归属和缺几何候选不会被此模块自动修复。

默认启用。`PCB_PIN_FIELD_RECOVERY=0` 关闭整个恢复阶段，恢复原输出。`configs/pin_field_recovery_v1.json` 默认每页最多 6 个元件、32 组候选、160 次本地 OCR；未触发条件的页面不加载模型。输入图像哈希与图结构的尺寸/坐标系不一致时拒绝恢复；失败时保留原结果并记录错误。

逐页日志为 `logs/<case>_pin_field_recovery.json`，包括采信、拒绝、OCR 预算、字段、网络变更及模型指纹。decision log 的 `pin_field_recovery` 提供摘要。

此策略针对数字字段与当前彩色原理图验证。没有识别的名称不会通过库规则或编号自动臆造；裸数字名称必须有内侧实际印刷字形证据。布局或颜色不满足证据条件时保留原值。
