# HALCON 第 11 周：程序工程化与 C#/C++ 集成

本周总目标：把一个已验证的 HDevelop 流程拆成可复用 Procedure，统一参数、错误、日志和资源管理，并完成一次 C# 或 C++ 最小可运行调用。

## 本周安排

| 天数 | 主题 | 主要成果 |
|---|---|---|
| 第 1 天 | Procedure 拆分和接口设计 | 清晰的输入输出契约 |
| 第 2 天 | 参数、错误码和日志 | 可配置、可诊断流程 |
| 第 3 天 | 句柄、图像对象和异常释放 | 资源生命周期清单 |
| 第 4 天 | HDevelop 代码导出 | 生成并整理 C#/C++ 代码 |
| 第 5 天 | 最小外部调用和计时 | 单图与批量调用成功 |
| 第 6 天 | 周项目 | 封装匹配或测量并集成 |
| 第 7 天 | 复盘 | 检查线程、模型和配置边界 |

## 核心概念

- Procedure 接口要表达业务：输入图像与配置，输出状态、数值、位置、分数和错误信息。
- 阈值、ROI、公差、模型路径等集中配置；不要硬编码在深层流程。
- 模型句柄、测量句柄、标定句柄和图像对象都有生命周期，异常路径也要释放。
- HDevelop 导出代码是起点，不是最终架构；应整理重复显示代码、全局状态和错误处理。
- UI 线程、采集线程和检测线程的对象所有权与线程安全要明确；本周先完成单线程最小闭环。

## 每日任务

### 第 1 天：Procedure

从第 6 或第 8 周选一个流程，拆成 `Initialize`、`Inspect`、`Visualize/FormatResult`、`Dispose` 等职责。写清图标与控制参数的方向和含义。

### 第 2 天：配置和错误

设计状态码：成功、无目标、低分、边缘不足、结果超差、输入无效、模型错误。为每个状态提供可读信息和必要上下文。

### 第 3 天：资源管理

列出所有创建/读取的句柄，注明创建位置、共享范围、释放位置和异常策略。长循环运行并观察是否持续增大资源占用。

### 第 4～5 天：导出与调用

导出到自己熟悉的 C# 或 C++，完成最小控制台或测试程序：加载资源一次、循环处理多张图、输出结果、最后释放。

### 第 6 天：周项目

输入为图像和参数；输出为状态、结果值、分数/位置、耗时和错误信息。完成 HDevelop 与外部语言同一批图片结果对照。

## 验收标准

- 主流程清晰，无大量重复算子和显示逻辑。
- 所有句柄正确释放，模型不在每张图片上重复加载。
- 参数可配置，错误码和日志足以定位失败阶段。
- C# 或 C++ 最小程序能批量运行，无需人工干预。
