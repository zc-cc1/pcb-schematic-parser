# 第三周第 5 天：亮度压力测试与结果统计

## 今日目标

今天不再增加新的分割算子，而是验证前面的方法是否稳定：

1. 冻结同一套参数，处理多种干扰条件。
2. 比较固定阈值与动态阈值的计数稳定性。
3. 记录正确计数、计数误差和运行时间。
4. 分析失败样本，而不是只展示成功结果。
5. 理解“数量正确”不一定等于每个目标都检测正确。

## 为什么要做压力测试

单张图片调通只能证明：

```text
这组参数在这一张图片上有效
```

工业现场会发生曝光漂移、光源衰减、局部阴影、反光、污染和噪声。如果每换一张图就修改参数，就无法判断算法是否真正稳定。

正确测试原则是：

```text
先冻结参数 → 再统一处理全部条件 → 最后统计成功和失败
```

真实项目应使用至少 30 张真实图像，并划分开发集、调参集和最终测试集。本程序的六组条件用于学习测试方法，不替代真实数据验证。

## 两条冻结的检测流程

### 固定阈值流程

```text
threshold 0～130
    ↓
connection
    ↓
按 width、height 筛选
    ↓
count_obj
```

### 动态阈值流程

```text
mean_image 151×151
    ↓
dyn_threshold Offset=15, dark
    ↓
connection
    ↓
按 width、height 筛选
    ↓
count_obj
```

两条流程对六组图都使用相同参数，不允许针对某一张失败图临时修改。

## 默认测试结果

目标真实数量为 7。默认结果为：

```text
固定阈值：[7, 0, 7, 7, 5, 7]
动态阈值：[7, 7, 7, 7, 6, 7]
```

对应计数误差：

```text
固定阈值：[0, 7, 0, 0, 2, 0]
动态阈值：[0, 0, 0, 0, 1, 0]
```

计数正确率：

```text
固定阈值：4/6，约 66.7%
动态阈值：5/6，约 83.3%
```

动态阈值对整体亮度变化更稳定，但局部阴影产生了突变边界，该边界可能与目标区域连接或破坏目标形状，最终仍漏掉一个目标。这说明局部阈值并不是万能方法。

## 计数误差与真实检测错误

本程序计算：

```text
计数误差 = abs(检测数量 - 真实数量)
```

但计数正确不能证明目标全部正确。例如：

```text
漏检 1 个真实目标 + 误检 1 个背景区域
                 ↓
总数仍然可能等于 7
```

真实项目还要逐目标匹配标注，分别统计：

- TP：正确检测。
- FP：误检。
- FN：漏检。
- Precision、Recall、漏检率和误检率。

## 运行时间的正确看法

程序使用 `count_seconds` 测量算法步骤，不把图形显示和 `stop()` 等待计入耗时。

首次运行可能包含缓存和初始化开销，因此正式统计应：

1. 先预热运行若干次。
2. 连续运行多轮。
3. 记录平均时间、最大时间和高分位时间。
4. 在相同硬件与相同线程设置下比较。
