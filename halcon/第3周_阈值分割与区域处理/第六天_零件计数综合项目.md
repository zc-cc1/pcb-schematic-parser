# 第三周第 6 天：零件计数与分类综合项目

## 项目目标

把本周学习内容组合成一条可批量运行、可统计、可解释的检测流程：

```text
构造测试集
  ↓
限制检测 ROI
  ↓
动态阈值分割
  ↓
connection 拆分候选
  ↓
宽高筛选
  ↓
圆度分类
  ↓
稳定排序与编号
  ↓
OK/NG、耗时和失败清单
```

## 检测任务

每幅图的真实结果为：

```text
零件总数：7
螺母：4
带齿零件：3
```

程序处理七种条件：

1. 原图。
2. 整体变暗 `0.35`。
3. 整体变暗 `0.55`。
4. 整体变亮 `1.20`。
5. 左侧局部阴影。
6. 椒盐噪声。
7. 极端欠曝 `0.05`。

前六组用于验证正常鲁棒范围；最后一组故意超出当前参数能力，用来验证 NG 判定和失败清单。

## 冻结参数

```text
固定阈值上限：130（仅作为基线对照）
动态阈值均值掩膜：101×101
动态阈值 Offset：15
有效宽度：50～130
有效高度：50～130
螺母圆度下限：0.55
```

所有测试图必须使用同一组参数。失败后先记录原因，不允许在循环中针对某个条件单独修改参数。

## 为什么加入 ROI

原图顶部存在一条暗色边界，它不是待测零件。程序用一个略小于整幅图的矩形 ROI 排除最外层边界：

```halcon
gen_rectangle1 (InspectionROI, 5, 5, Height - 6, Width - 6)
reduce_domain (TestImage, InspectionROI, TestImageReduced)
```

ROI 的作用是限制检测范围，不是替代目标筛选。真实项目中的 ROI 应根据工装和目标可能出现的位置确定，并预留机械位置波动余量。

## 为什么项目使用 `MeanMask=101`

第 5 天使用 `151×151` 掩膜时，突变阴影产生的宽阈值带会与一个目标连接，目标随后因宽高超限而被删除。实验表明 `101×101` 在当前目标尺寸和阴影位置下能保持七个零件完整。

这不是“101 永远最好”，而是说明掩膜必须结合：

- 目标尺寸。
- 背景变化尺度。
- 目标之间的间距。
- 干扰边界的位置。

## 分类规则

宽高筛选先得到七个有效零件，再根据圆度分类：

```text
circularity >= 0.55 → 螺母
circularity < 0.55  → 带齿零件
```

每个条件都验证：

```text
总数 == 7
并且 螺母 == 4
并且 带齿零件 == 3
```

只有三个条件全部满足才判定为 PASS。

## 可视化颜色

- 红色：动态阈值产生、但未必通过尺寸筛选的全部候选连通域。
- 青色：圆度较高的螺母。
- 橙色：圆度较低的带齿零件。
- 绿色：有效零件的轴对齐外接矩形。
- 蓝色：检测 ROI。

如果某个有效目标先以红色显示，随后会被青色或橙色轮廓覆盖；最终仍为红色的区域就是被排除的候选干扰。

## 默认统计结果

```text
固定阈值计数：[7, 0, 7, 7, 5, 7, 0]
最终流程计数：[7, 7, 7, 7, 7, 7, 0]
螺母计数：    [4, 4, 4, 4, 4, 4, 0]
带齿件计数：  [3, 3, 3, 3, 3, 3, 0]
通过条件：6/7
失败条件：极端欠曝 0.05
```

极端欠曝时，背景与目标的剩余灰度差小于固定的 `Offset=15`，动态阈值无法产生完整目标。这是当前算法的明确工作边界。

## 关于漏检和误检统计

程序给出的 `MissedEstimates` 与 `ExtraEstimates` 只根据数量差估算：

```text
检测数少于 7 → 估计漏检
检测数多于 7 → 估计多检
```

它不能识别“漏掉一个真目标，同时误检一个假目标，数量仍为 7”的情况。真实项目必须使用逐目标标注和空间匹配统计真正的 FP/FN。

## 项目验收问题

1. 为什么最终 PASS 不能只判断总数等于 7？
2. ROI 在本项目中解决了什么问题，又可能引入什么风险？
3. 为什么将 `MeanMask` 从 151 调整到 101 能改善局部阴影条件？
4. 极端欠曝 `0.05` 为什么会超过动态阈值的能力范围？
5. 为什么仅凭数量差不能准确统计真实误检和漏检？

能够清楚回答四题，并独立修改一种压力条件、解释结果变化，即完成第三周核心项目。
