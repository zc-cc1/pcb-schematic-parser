# 三个元器件库：怎么用、实测到什么程度

> 全部数字由 `_derive/analyze_official.py`、`analyze_official2.py`、`build_artifacts.py` 生成，可重跑。

## 1. 三个库是什么

| 文件 | 条目 | 每条字段 | 引脚行数 | 有无符号几何 |
|---|---:|---|---:|---|
| `BoxICLibrary.json` | **1000** | 只有 `pins` | 24,708 | **无**（连 `esym_path` 都没有） |
| `BoxICLibrary_200cases.json` | 360 | `esym_path` + `pins`（241 条还带 `same_hash_components`） | 13,600 | 仅文件名，`.esym` 文件未提供 |
| `cpntLibrary` | 337 | `esym_path` + `pins` + `same_hash_components` | 9,762 | 同上 |

关系（都是 EasyEDA 符号池的不同切片，**按型号键合并去重后共 1186 个**）：

```
BoxICLibrary.json (1000)  ⊇  BoxICLibrary_200cases.json (360)        重叠 360
BoxICLibrary_200cases.json (360) ∩ cpntLibrary (337) = 145          各自独有 215 / 192
```

- `cpntLibrary` 的独有键多是**带料号后缀的同名变体**（`AMS1117-3.3_C6186`、`AMS1117-3.3_1839`…），
  真正新增的型号很少。→ **主力用 `BoxICLibrary.json`**，`cpntLibrary` 只用来补漏。
- 新版 `BoxICLibrary.json` 已补上 Q&A 一般 #7/#15/#19 承诺补齐的 IC：
  `STMPS2141STR`（10GT case6 的 U2/U4）、`MP2236CGJ-Z`（case7 的 U1）**都已在库中**，
  且引脚数与 open_GT 完全一致（5 脚 / 8 脚）。

## 2. 能查到什么：型号 → 引脚（编号 + 名称）

以 `open_GT`（Name 是**型号**的那 13 例）为基准，实测结果非常好：

| 检查项 | 结果 |
|---|---|
| box/ic 元件中型号能在库中查到 | **28 / 31**（3 个查不到的：`5V2A in`、`5V2A out`、`H1`——都是非芯片的框/座） |
| 其中**引脚编号集合与 GT 完全一致** | **28 / 28** |
| 其中**引脚名称集合与 GT 完全一致** | **19 / 28**（68%） |

逐例（编号全部一致）：

| 元件 | GT 脚数 = 库脚数 | 名称也一致 |
|---|---:|:--:|
| `IP5306-4.35V`、`SX1308`、`XB7608A`、`HS96L03W2C03`×4、`SY8113BADC`、`XC6206P332MR`、`TP4054-MS`、`TPS61240DRVR`×2、`78M12`×2、`STMPS2141STR`×2、`MP2236CGJ-Z`、`PAW3395DM-T6QU`、`MT2492`、`EG1192L`、`CJ78L05`、`TP4333`、`TYPE-C 6P(073)`、`AF 90° WJDG`、`SY6912AFCC`、`RT7272BGSP`、`AMS1117-3.3`（open_GT/4） | ✔ | ✔ |
| `AMS1117-3.3`（open_GT/5） | ✔ | ✘（别名选错，见下） |

**为什么名称只有 68%**：库的 `pins` 是“多个同源符号实例”的聚合，同一编号挂了多个别名。
`AMS1117-3.3` 的 1 号脚在库里同时有 `GND / ADJ / GND/ADJ / ADJ(GND) / ADJ/GND / VSS/ADJ` 六种写法，
GT 用的是 `ADJ(GND)`。→ **编号是确定的，名称是候选集，必须在候选里选。**

## 3. 训练集/评测集的可查率

| 数据 | box/ic 元件 | 型号可查（`BoxICLibrary`） | 备注 |
|---|---:|---:|---|
| `open_GT`（13 例） | 31 | 28（90%） | Name=型号 |
| `200_train_cases` | 973（960 `box` + 13 `block`） | **552（57%）** | 728 个元件 `Name != key`（即 Name 是型号） |
| `10_GTcase`（10 例） | 15 | **0 个可用** | **全部 `Name == key`（`U1`），不是型号** |

第三行是**关键陷阱**：10GT 的 184 个元件全部 `Name == key`；而库里恰好有一个真名叫 `U1` 的元件，
于是 `"U1" in library` 会返回 True——**这是假命中**，会拿到完全无关的 30 脚符号。
判定条件必须是 **`Name != key`**（open_GT 里 41/346 满足，10GT 里 0/184 满足）。

## 4. 引脚编号的“漂移”反例（必须挡住）

库的编号并不总是等于 GT 的编号，已知两处：

| 元件 | GT | 库 | 说明 |
|---|---|---|---|
| `IR4428`（10GT 0099） | 8 脚，含 `6`，无 `9` | 8 脚，含 `9`，无 `6` | 符号版本差异，编号整体漂了一位 |
| `S-8252 Series` | 5 脚（3/4/5…） | 含 `26/27/C2` | 库里混入了别的封装/符号实例 |

`configs/box_ic_library_v1.json` 里已经写了对应规则（`observed_number_is_never_overwritten`、
`consistency_gate`），方向是对的；但**现有的 A/B 违反了它**：
`reports/box_library_ab.json` 的记录显示脚本把 `DRV8824-Q1` 的 6 号脚改成了 `6_1/6_2`、
把 `S-8252` 的 3 号改成 `26`、`IR4428` 的 6 号改成 `9`，并因此写了 `pins_renumbered`。
GT 里不存在 `pin_6_1`，这类改动只会制造 FP + 错的 net 成员。

**另一类必须先清洗的编号**：库里形如 `1_1`、`6_2` 的编号是聚合去重用的后缀
（`BoxICLibrary.json` 138/24,708 = 0.6%，`BoxICLibrary_200cases.json` 138/13,600 = 1.0%，`cpntLibrary` 0 个），
写入 `pin_<number>` 前必须剥掉后缀或整条丢弃。

## 5. 库**不能**做什么

1. **拿不到几何**：新版库没有 `esym_path`，旧库只有文件名、`.esym` 本体未提供。
   → 不能从库里得到“哪根引脚画在哪个位置”。
2. **不能按位置猜编号**：实测 25 个可判定的 open_GT box 元件里，
   按方位角排序能复现编号顺序的只有 **6 个**（且 `pin_1` 的方位角散布在 14°–349°），反向 0 个。
   所以“从顶边起顺时针编号”这种规则站不住。**编号→坐标只能靠“编号→名称（库）+ 名称→位置（丝印 OCR）”。**
3. **名称→编号不是一一映射**：`AMS1117-3.3` 里 `GND` 同时挂在 1 号和 3 号、`VOUT` 挂在 2 号和 4 号。
   → 必须做**全局一对一分配**（观测到的丝印名 × 库的 `(number,name)` 多重集求最大匹配），不能逐条 `name→number` 查表。

## 6. 推荐用法（按证据排序）

```
输入：一个 box/ic 元件的 bbox + 框内 OCR 到的型号文本 + 检测到的引脚 tip 坐标 + tip 附近的丝印文本
1) 型号归一化（去空格/连字符/大小写）后查合并索引，且要求 Name != key、型号含数字、长度 ≥4
2) 命中后：
   a) 编号集直接取自库（先剥掉 `_1/_2` 后缀）——这一项在 open_GT 上是 100%
   b) 用库的 (编号,名称) 多重集与观测丝印做最大二分匹配；未匹配上的名称按库内该编号的别名频次兜底
   c) **已观测到的编号永不覆盖**（IR4428 / S-8252 就是反例）
   d) 一致性校验：同时带编号和名称的引脚，库必须复现 ≥60% 才采用该条目（config 里的 `min_consistency`）
3) 位置：只来自图像（检测/U-Net），库不参与
4) 没有命中型号时：退回“按 pin number 自动编号（官方 p17 规则）+ 名称留空”，
   但**不要把这类 pin 当作网络导出的硬失败**（见 01 文档第 5 节 GND/VCC）
```

## 7. 现成工件：`_derive/box_model_index.json`

三库合并、归一化键、引脚已去重，394 KB，可直接 `json.load`：

```json
{
  "ip53064.35v": {
    "keys": ["IP5306-4.35V"],
    "sources": ["BoxICLibrary", "BoxICLibrary_200cases"],
    "pins": [["1","VIN"],["2","GND"],["3","VBAT"],["..."],["9","GND"]]
  },
  "ams11173.3": {
    "keys": ["AMS1117-3.3"],
    "sources": ["BoxICLibrary","BoxICLibrary_200cases","cpntLibrary"],
    "pins": [["1","GND"],["1","ADJ"],["1","ADJ(GND)"],["2","VOUT"],["..."],["4","TAB"]]
  }
}
```

- 键：`re.sub(r"[\s\-_]+","",型号).lower()`（与 `build_artifacts.py` 一致，查询时用同一函数）。
- `pins` 是 `(编号, 名称)` 去重后的多重集，**同一个编号会出现多次**（别名），这正是第 5 节要消歧的输入。
- 有 34 个条目引脚数 > 64（聚合了畸形符号），可按脚数上限过滤。

## 8. 一句话结论

> 库解决的是**“这个 box 的 1 号脚叫什么、一共有几号脚”**，在型号可读时几乎白给（编号 100%、名称候选 100%）；
> 它**不解决**位号识别、引脚位置、网络连通。所以正确的期望是：把库当成
> “pin 键名与 pin 名候选的字典”，而不是“自动出 pins 段”的生成器。
