## 二、九条关键结论（都带数字）

1. **box 元件的引脚编号可以“免费”从库里拿到。**
   在 `open_GT` 的 31 个 box/ic 元件中，型号能在库中查到的 28 个，其引脚**编号集合与 GT 完全一致：28/28**。
   也就是说型号一旦确定，`pin_1..pin_n` 的键名不需要猜。

2. **引脚名称只能取“候选”，不能直接抄：19/28 完全一致。**
   库的 `pins` 是多个同源符号实例的聚合，同一个编号会挂多个别名。例：`AMS1117-3.3` 的 1 号脚同时有
   `GND / ADJ / GND/ADJ / ADJ(GND) / ADJ/GND / VSS/ADJ`，而 open_GT/5 的 U3 用的是 `ADJ(GND)`。
   名称必须靠图中丝印（OCR）在候选集里消歧。

3. **Q&A 欠的账已经还了。** Q&A 一般 #7/#15/#19 说 10GT 里缺的 IC 会在最终库补齐：
   `STMPS2141STR`（case6 的 U2/U4）、`MP2236CGJ-Z`（case7 的 U1）**现在都已在 `BoxICLibrary.json` 中**，
   且引脚数与编号与 open_GT 完全一致。

4. **10GT 的 `Name` 还是位号，不是型号。** 10GT 184 个元件全部 `Name == key`（如 `U1`）；
   而 `open_GT` 的 box 元件是 `"Name": "IP5306-4.35V"`，这才是 Q&A 一般 #10（“key 填 U1 U2，name 是芯片名字”）的口径。
   副作用：按 `Name` 查库时 `"U1"` 会假命中库里真有一个叫 `U1` 的元件——**必须排除“Name==位号”的元件**。

5. **坐标系是左下原点、Y 向上，不是 PNG 的像素坐标系。**
   实测 0025：GT 引脚点直接取坐标，只有 5/18 落在墨迹上；按 `y → H−y` 翻转后 **17/18** 落在墨迹上。
   0100 的元件框墨迹密度也是翻转后更高（0.116 → 0.247）。这与 Q&A 一般 #11 一致，`README.md` 的旧说法作废。

6. **判分口径（PDF 第 7–8 页 + 平台 `summary.json`）：** 权重 `.30 / .25 / .35 / .10`
   （元件 / 引脚 / 网络超图 / 网络线段）。**元件按 key 匹配，bbox 不参与匹配**，
   只有 key 命中后再校验 `type` 与 bbox 误差 **20 px**；引脚按 component key + `pin number` 匹配，
   再校验 `pinname` 与 **5 px**；线段端点 **5 px** 且 `edges` 条数要准。
   非 box 元件的 pinname、pinnumber **不参与评分**（Q&A 评测 #2、#6）。细则见 `01_官方判分规则速查.md`。

7. **`type_list`（官方 34 类）至今没到手。**
   Q&A 一般 #3/#4/#14/#17 反复说“以 `type_list` 为准、评测不会超出该表”，但本文件夹与公开数据集中都没有这个文件。
   目前可用的替代：`open_GT ∪ 10GT` 实测 **21 类**（已确认子集），四份资料并集 **43 类**，见 `03_type与标注约定.md`。
   **建议立刻向官方索取 `type_list`。**

8. **`components.bbox` 是“本体框”，所有引脚 tip 都在框外。**
   open_GT 的 191 个 box 引脚点 **100% 落在 GT 框外**（10GT 是 94%）；引脚到框边距离中位 **20 px**、最大 40 px，
   45 个 box 元件里有 **10 个 > 20 px**。而官方 bbox 容差正好是 20 px。
   → 提交“含引线的检测框”会平白丢掉约 22% 的 box 元件。详见 `03_type与标注约定.md` 第 4 节；
   内缩到底能换多少分、以及为什么**不建议**运行时统一内缩，见 `04_实测_导出与评分口径.md` 第 3 节。

9. **库对 PinF1 是「锦上添花」，卡点在位号。**
   10GT 的 378 个引脚里只有 **101 个**属于 box/ic（库能作用的面）；这 101 个里
   **80 个（79%）已经有 ≤5 px 的对应预测点**，但只用当前键能计分的只有 **4 个**——
   其余全挂在 `DET_00xx` 自动键下（box 元件位号没读出来）。
   把位号修好、再接库，TP 可到 **58**，PinF1（box 口径）**.076 → .730**。
   详见 `05_有了元件库_pins能提升多少.md`。

## 三、和“目前的困难”的对应关系

现状（来自 `评测结果/` 与 `D:/pcb_unet_v2/reports/`）：平台七轮最好 34.65 分；第七轮
元件 / 引脚 / 连通 / 线段 = `.7108 / .4376 / .0330 / .0107`。连通与线段合计 **45% 权重长期接近 0**，
因为提交包从来没有导出过网络（平台解析出 `nets: 0`）。本地参考实现在 10 例 Golden 上：
元件 `.2397`、引脚 `.1528`、网络超图 `.0392`（`reports/box_library_ab.json`）。

| 卡点 | 官方资料里能直接解决的部分 | 具体动作 |
|---|---|---|

## 四、三条“别踩”的坑（都是实测出来的）

1. **不要用 `Name` 查库去判断“这个元件在不在库里”**——10GT 的 `Name` 是位号，`U1` 在库中恰好存在，会得到假阳性。
   判定条件：`Name != key`（10GT 里 0/184 满足，open_GT 里 41/346 满足）。
2. **不要把库里的引脚编号原样写进 `pin_<number>`**——聚合条目里重复编号带 `_1/_2` 后缀
   （`BoxICLibrary.json` 138/24,708 = 0.6%，`BoxICLibrary_200cases.json` 1.0%）。
   GT 里不存在 `pin_6_1`。已有的 A/B 就把 `DRV8824-Q1` 的 6 号脚改成了 `6_1/6_2`、把 `S-8252` 的 3 号改成 `26`，这两处要回退。
3. **不要按“从顶边起顺时针”这类几何规则给 box 编号**——25 个可判定元件里只有 6 个能用单一角向顺序复现，
   `pin_1` 的方位角散布在 14°–349°。库也没有 `esym_path`（新版 `BoxICLibrary.json` 只有 `pins`），拿不到符号几何。
   编号→坐标的绑定只能靠“编号→名称（库）+ 名称→位置（丝印 OCR）”。
