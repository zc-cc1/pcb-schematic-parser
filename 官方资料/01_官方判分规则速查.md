## 1. 总分怎么来的

```
FinalScore_Accuracy = 0.95 × Score_Accuracy + 0.05 × (m/M) × Score_Token      （PDF p6）
Score_Accuracy      = 所有 case 的 Score_Accuracy_SingleCase 求平均，0–100
Score_SingleCase    = 100 × ( 0.30·ComponentF1 + 0.25·PinF1 + 0.35·NetHypergraphF1 + 0.10·NetLineF1 )
```

- **Token 只占 5%，而且是名次赋分**（消耗越少赋分越高，PDF p6–p7）。Q&A 评测 #11：总 token = 输入 + 输出，等权。
- **附加分 10 分**（`FinalScore_Data`）：提交自采数据，`每组不超过 10 例`，计入 PCBnet 开源数据集；
  最低数据量与计分办法在尚未发布的《数据提交说明》里（PDF p9–p10）。
  数据集地址：<https://github.com/ECNUACRush/PCBnet/>

## 2. 四项指标：怎么匹配、怎么判对

| 指标 | 权重 | 匹配方式 | 判对条件 | 出处 |
|---|---:|---|---|---|
| ComponentF1 | .30 | **直接用 key（designator）匹配**，`GT.U3` 只和 `Pred.U3` 比 | ① key 命中 ② `type` 正确 ③ bbox 误差 ≤**20 px** ④ 需要文本时严格一致 | PDF p7；p17 注 b“bbox 不用于 component 匹配，只在 key matched 的元件上算坐标误差” |
| PinF1 | .25 | 先 component key 匹配，再按 **pin number** 匹配（不是最近点匹配） | ① `pinname` 对 ② `pinnumber` 对 ③ 坐标距离 ≤**5 px** | PDF p8、p18 注 a |
| NetHypergraphF1 | .35 | 每个 net 当 pin set，pred/GT 之间做**匈牙利匹配** | 该 net 内的 `component.pin_number` 是否都正确出现 | PDF p8 |
| NetLineF1 | .10 | 只在**已匹配的 net 对**内比较，每条 `edge_i` 是一条线段 | 两个端点都 ≤**5 px**；`edges` **条数也要准**，多一条少一条都扣 | PDF p8、p20 注 |

**文本比较规则（PDF p7、p17 注 c）**：`ic`（= GT 里的 `box`）比 `Name`；`resistor`/`capacitor`（= `r`/`c`）比 `value`；
其他类别**不比较文本**。字符串**严格匹配**：`10k` / `10K` / `10K ` 是三个不同字符串（PDF p8 注 b、p30 注 6）。

**坐标系**：左下角原点，x 向右、y 向上增大；bbox 为 `[x1,y1,x2,y2]`（左下、右上）；单位是图片像素（PDF p11、p26）。
实测印证见 `03_type与标注约定.md`。

## 3. 引脚（PinF1）的四条硬规则

1. **key 必须是 `pin_<pinNumber>`**，因为 pin matching 直接吃这个键（PDF p18 注 b、p30 注 2）。
2. **pinNumber 为空/占位符 `∅`/OCR 噪声时，官方转换器自动编号为 `pin_1、pin_2…`**（PDF p17）。
3. **一个引脚多编号时（如 `"5,6,7,8,9"`）拆成 `pin_5、pin_6…` 多条独立条目**（PDF p18 注 d）——我们还没实现。
4. **同一 `pin.A5` 与 `pin_A5`**：`hyperGraph` 里写 `U1.A5` 对应 `pins.U1.pin_A5`，两处必须对齐（PDF p30 注 3）。

**引脚坐标怎么取（附录三，PDF p26–p29）**：每个元件有外侧框（outer bbox）和内侧框（body bbox）；
引脚 **tip 在外侧框边缘**，base 连到内侧框。两种连接方式：
- 导线连引脚：绿导线与引脚的**交界点**就是坐标；
- 引脚直接连引脚：两个 tip 点**重合**，坐标相同，没有导线。

> 代码里必须区分 `outer bbox` 与 `body bbox`：`components.bbox` 用的是哪一个，官方没写死
> （Q&A 一般 #23/#27/#28 都在问这个，官方统一回答“以即将更新的 10GT 为准”）。

## 4. 网络（NetHypergraphF1 / NetLineF1）

- `hyperGraph` 格式 `(component_id.pin_number,…)`，如 `(U1.A5,R1.1)` → 解析为 `U1.pin_A5`、`R1.pin_1`。
- **net key 本身不要求和 GT 一致**（PDF p8 注 c、p30 注 4）——net 靠 hyperGraph 内容做匈牙利匹配。
- `edges` 每个 `edge_i` **必须恰好 2 个点**；多折点导线要拆成多条 `edge_i`，不能写成 `[p1,p2,p3]`（PDF p20）。
- **零长度线段合法**（起点=终点），飞线 net 的 edges 通常就是这么表示的（PDF p20、p23）。
- **飞线（flywire）**：同一 net 名下有多个**非同 VCC/GND** 的同名测试点/网络标签时，
  它们逻辑上属于同一个 net，`hyperGraph` 必须包含**所有**逻辑相连引脚，漏一方就算连错（PDF p21–p23）。
  VCC/GND 的多同名符号**不按飞线处理**，按普通电源网络对待（PDF p23 注 a）。
- **线段几何必须放在正确 net 的 edges 下**，放错 net 不会因为位置接近而得分（PDF p30 注 5）。

## 5. GND / VCC 专项（最容易白丢分的地方）

| 事项 | 官方口径 | 出处 |
|---|---|---|
| GND/VCC 的 pin number 怎么来 | **随机生成**，图里看不出来 | Q&A 一般 #5、#29 |
| 这些编号参与评分吗 | **不参与**；GND 的序号名不影响评分 | Q&A 评测 #4、#5 |
| 那怎么匹配 | “Vcc 和 gnd 是 `∅`，直接是**坐标匹配**” | Q&A 评测 #1、#4 |
| 多个同名 GND/VCC 是一个 net 还是多个 | **打分时会合并成同一个 net** | Q&A 评测 #6、#9 |
| 历史上踩过的坑 | 平台曾要求 GND/VCC 键名与 GT 完全一致，导致这部分**大面积误判丢分**；官方答“**评测代码会更新**” | Q&A 评测 #7 |

**工程结论**：把 GND/VCC 的引脚从“身份未解析 → 整条网络被拦”的闸门里**摘出去**，按坐标/元件做等价匹配。
当前提交包 47/48 条网络正是被 `contains_pin_with_unresolved_identity_number_or_name` 拦掉的
（`评测结果/第七次评测…/*_engineering_export_coverage.json`）。

## 6. 什么是“不参与评分”的（可以省算力）

| 对象 | 结论 | 出处 |
|---|---|---|
| 非 box（ic）类元件的 `pinname` / `pinnumber` | **不参与评分** | Q&A 评测 #2、#6 |
| 非 box 元件的文本 | 不比较 | PDF p7 |
| 纯文字网络名（`PA1`、`GPIO_5` 这类） | **不要**作为元件标注 | Q&A 一般 #30 |
| 黑白/带框图片 | 最终评分案例**不会**出现 | Q&A 一般 #13、#22 |

## 7. 类型与归属（会影响 ComponentF1 的 type 一项）

- 排针、USB 座等连接器（位号 `H1`、`USB1`）**type 属于 `box`**（Q&A 一般 #18、#30）。
- `type` 以官方 `type_list` 为准（34 类），**评测不会超出该表**（Q&A 一般 #3/#4/#14/#17）——**该表尚未到手**。
- 评测 case 的元件**不会缺 designator**（Q&A 一般 #12），designator 以图片显示为准。

## 8. 提交与评测环境

- 提交 JSON 格式**以 10GT 为准**（Q&A 评测 #8；平台“提交示例 README”的格式与赛题指南不一致时听 10GT）。
- 只提供 **Qwen3.8** 的大模型 API；**大模型调用耗时计入解题总时间**（Q&A 模型 #1、环境 #5）。
- **不允许本地部署大模型**；但 **YOLO 等 CV/深度学习模型允许自由使用**，“不建议部署参数规模超过赛题 API 模型规模的 LLM”
  （Q&A 模型 #1）。→ 自训 YOLO/U-Net 合规。
- 硬件：**A800 × 8**；可挂 GPU；允许自行升级 PyTorch/CUDA（Q&A 环境 #2、#3、#7）。不提供大模型训练环境（环境 #1）。
- 正式评测：**所有图片一次性提供，允许并行处理**（Q&A 环境 #5）。
