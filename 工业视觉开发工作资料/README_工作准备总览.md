# 工业视觉开发工作准备总览

更新日期：2026-08-09

## 先说结论

工业视觉开发不是只写图像算法。能够独立完成下面这条闭环，才接近“可上岗、可交付”：

> 明确检测标准 → 采样和可行性验证 → 相机/镜头/光源选型 → 稳定采图与触发 → 算法和标定 → 上位机与 PLC/机器人联调 → 压力测试 → 文档、验收和售后

结合当前目录已有的 HALCON 20.11 学习材料和工业相机手册，最适合先走的方向是：

**2D 机器视觉应用/集成工程师：C# + HALCON + 工业相机 SDK + TCP/Modbus。**

先把一条 2D 检测链路做完整，再根据兴趣分支到 C++ 高性能开发、深度学习缺陷检测，或 3D/机器人视觉。不要同时学习三门语言和三套视觉库。

## 三类岗位不要混淆

| 方向 | 日常工作重点 | 第一技术栈 | 入门优先级 |
|---|---|---|---:|
| 视觉应用/集成工程师 | 方案、选型、算法、上位机、PLC/机器人联调、现场交付 | C# + HALCON/VisionPro + 相机 SDK | 推荐先学 |
| 视觉软件/平台工程师 | 模块化架构、相机抽象、多线程、性能、数据库与部署 | C++ 或 C# + OpenCV/HALCON | 第二阶段 |
| 视觉算法工程师 | 传统算法、深度学习、数据闭环、模型部署与优化 | Python/PyTorch + C++/ONNX | 有算法基础后分支 |
| 3D/机器人视觉工程师 | 点云、坐标系、手眼标定、抓取/测量 | C++/Python + 3D SDK + 机器人 SDK | 进阶分支 |

## 一套够用的起步工具

- Windows 工控机或普通开发电脑；Git；Visual Studio。
- HALCON 20.11 + HDevelop；C#/.NET 作为第一套交付语言。
- 一台 GigE 或 USB3 面阵相机、合适镜头、可调光源；没有硬件时先使用离线图片和厂商 Viewer/SDK 示例。
- 标定板、尺规/标准件、遮光材料；做测量项目时不要用普通打印纸替代精密标定板作为最终验收依据。
- Wireshark、串口/Socket/Modbus 调试工具、PLC 模拟器；有条件再接真实 PLC、传感器和光电触发。

## 上岗前最低成果

- 至少 2 个完整项目，最好 3 个；每个项目有需求、数据、代码、结果、失败样本和测试报告。
- 能解释为什么选择某种相机、镜头和光源，而不只是会调算法参数。
- 能完成外触发采图，处理超时、断线重连、丢帧和异常日志。
- 能把检测结果通过 TCP 或 Modbus 与模拟 PLC/真实 PLC 交换。
- 能用数据回答准确性、重复性、误判、漏检和节拍，而不使用“看起来效果不错”作为结论。
- 能写一页中文简历，并在 5 分钟内讲清一个项目的需求、难点、取舍、指标和复盘。
