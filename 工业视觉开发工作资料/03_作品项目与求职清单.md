# 作品项目与求职清单

## 作品集原则

招聘方要看的不是“用了多少算子”，而是你能否把不稳定的现场问题变成可交付系统。每个项目至少展示：

- 明确的检测对象、OK/NG 定义、精度、节拍和接口。
- 成像对比与硬件选择理由。
- 算法流程及关键参数，而不是只放最终框选图。
- 采集、处理、通讯、UI、日志的系统架构。
- 独立测试集上的数据指标和失败样本。
- 你负责的部分、遇到的故障、取舍和后续改进。

## 建议完成的三个项目

### 项目一：零件定位、计数与尺寸测量

目标：证明经典视觉、标定和测量能力。

- 工件存在/缺失、数量、孔径或边距测量。
- 包含背光或稳定正面光的成像对比。
- 完成标定、定位、ROI 跟随、亚像素边缘和 OK/NG 判定。
- 测试不同位置、角度、亮度和至少两个批次。
- 记录重复测量极差/标准差、与基准量具的偏差、单张耗时。

### 项目二：旋转零件定位与 PLC 握手

目标：证明模板匹配、工程软件和自动化集成能力。

- 软触发与模拟硬触发两种采图模式。
- 输出 X、Y、角度或像素位置；有条件时转换为世界坐标。
- 实现“触发、忙、完成、OK/NG、结果、复位、超时”的状态机。
- 模拟断网、相机拔插、超时、重复触发和配置损坏。
- 通过 Modbus TCP 或 Socket 与模拟 PLC/另一进程联调。

### 项目三：表面缺陷检测

目标：证明你会处理数据和鲁棒性，而不只是做演示图。

- 收集正常、划伤、脏污、缺口等类别，并保留难例。
- 先做定位、对齐、差分/纹理/形态学基线。
- 如果传统方法边界不稳定，再增加 HALCON 深度学习或 PyTorch 分支。
- 将开发、调参和测试样本按批次隔离，避免同一连拍序列跨集合泄漏。
- 报告按缺陷类型统计的检出率、漏检数、误杀数和处理耗时。

## 每个项目的最低验收材料

- [ ] 一页需求与可行性评估。
- [ ] 系统结构图和处理流程图。
- [ ] 相机、镜头、光源、工作距离和视野参数。
- [ ] 不少于 3 种成像/参数对比。
- [ ] 可复现代码和配置文件。
- [ ] 原图只读保存，结果图和日志单独存放。
- [ ] 开发集、调参集、测试集分开。
- [ ] 误判和漏检样本清单。
- [ ] 平均、P95、P99 处理耗时；说明是否包含采图与通讯。
- [ ] 连续运行和异常恢复记录。
- [ ] 2～5 分钟演示视频。
- [ ] README 中写清运行环境、启动步骤和本人贡献。

## 简历项目写法

使用“对象 + 任务 + 方法 + 工程化 + 指标”的结构，避免只列软件名。

示例骨架：

> 面向某零件的孔径与缺口检测，完成相机/镜头/背光方案验证；基于 HALCON 实现模板定位、ROI 跟随和亚像素测量，以 C# 集成相机 SDK、Modbus TCP、配置与日志；在按批次隔离的测试集上统计漏检、误杀、重复性和 P95 节拍，并完成断线重连测试。

指标必须填写真实测试值；没有测试就不要编造百分比。

## 面试前必须能回答

### 成像与硬件

- 如何根据视野和最小特征估算相机分辨率？为什么不能把“一个像素”当成可靠检测下限？
- 全局快门和卷帘快门有什么差别？运动工件如何控制拖影？
- 什么时候用背光、同轴光、低角度光、穹顶光或偏振？
- 曝光、增益、光圈、景深和噪声之间如何取舍？
- GigE 丢帧会从网卡、线缆、包长、带宽、缓冲和线程哪些层面排查？

### 算法与标定

- 阈值、形态学、轮廓、XLD、模板匹配分别适合什么问题？
- 为什么要先定位再做局部检测？
- 如何验证测量重复性和标定是否可靠？
- 漏检与误杀哪个更严重？阈值如何根据工艺风险确定？
- 什么情况下传统视觉优于深度学习？什么情况下应转向深度学习？

### 软件与现场

- 相机采集线程、算法线程和 UI 线程如何解耦？
- 相机断开、PLC 重复触发、算法超时和磁盘满时系统怎么办？
- 参数如何保存、版本化、回滚并与产品型号绑定？
- 如何保证原图、结果、工件序号和时间戳可追溯？
- 到现场后画面不稳定，你按什么顺序排查？

## 投递准备

- 一页简历；项目写结果与责任，不堆课程名称。
- 作品集首页先放最完整、最匹配岗位的项目。
- Git 仓库或压缩包去除授权库、客户数据、账号、IP、密码和公司机密。
- 针对岗位选择版本：应用岗突出选型和联调；软件岗突出架构和稳定性；算法岗突出数据、指标和泛化。
- 阅读目标公司的产品、客户行业、常用平台和出差要求，准备 5 分钟项目讲解和 15 分钟深入问答。
