# 新评分规则（2026-10-18）对我们意味着什么

官方宣布四条变化：
① 空间阈值 5px → **20px**（元件 bbox、IC 引脚、导线端点共用）
② 普通元件的 pin 不再计位置分、不再按 pin 计连接关系分
③ 连接关系改两级：普通元件按**整体**对齐，IC 仍按 pin
④ GND/电源符号不再按自动编号的 key 对齐，改按**类别 + 值 + 几何位置**匹配

## 1. 先说一个反推出来的事实：第 8 次评测**已经是新规则**

用新规则（20px）去算第 8 次提交的那一版：

| 分项 | 我的新规则复算 | 平台第 8 次公布 |
|---|---:|---:|
| component | **0.687** | **0.6874** |
| pin | **0.574** | **0.5739** |
| connectivity | 0.398 | 0.480 |
| wire | 0.380 | 0.315 |
| 总分 | 52.71 | 54.92 |

元件和引脚**逐位对上**——而用旧的 5px 口径算引脚只有 0.567。所以平台的引脚阈值一直是 20px，
`R07 的 5px` 是我从早期报告里抄错的口径。**今天的本地分从此刻起都要用 20px 复算。**

（连通我偏低 0.082、导线我偏高 0.065，是两边实现差异，见第 4 节。）

## 3. 四条规则分别意味着什么

| 变化 | 对我们的影响 | 结论 |
|---|---|---|
| ① 20px | 我们引脚中位偏差 2px，本来就在 5px 内；真正受益的是**导线**（端点中位偏差 15px，原来全判错，现在多数能过）：0.211 → **0.415** | **几何精度不再是瓶颈，别再调点位** |
| ② 普通引脚不计分 | 我本地实现一直是 IC-only，所以分数没变；但说明**被动件的引脚编号、引脚名一律不用做** | 之前计划的"被动件编号"作废 |
| ③ 连通两级 | 我实现里普通元件本来就是整体顶点，所以没变化；含义是**被动件只要元件 key 对**，它在网里就算一个完整顶点 | 被动件的引脚不必求准 |
| ④ 电源按类别/值/几何 | 把电源顶点的端口号去掉后重算，13 页**没变化**（0.556 两边一样） | 我们电源符号的 key 本来就没影响 |

## 4. 两处实现差异（不是提交的问题）

| 分项 | 我的复算 | 平台 | 原因推测 |
|---|---:|---:|---|
| 连通 | 0.398 | 0.480 | 平台对**同名电源网络做了合并**后再匹配，我的合并不彻底 |
| 导线 | 0.380 | 0.315 | 我按"逐条网络贪心配对"，平台可能只对**已匹配的连通网络对**比线段 |

**结论：连通的本地分是下界（平台更高），导线的本地分是上界（平台更低）。**
