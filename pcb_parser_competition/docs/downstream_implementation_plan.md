## 1. OCR与元件文字绑定——立即推进的开发阶段

输入：原始PNG、检测框及类别。

处理：保留整图OCR，增加原图分块/元件周围局部OCR和90度方向尝试；合并重叠识别结果并恢复原图坐标。文字按位号、型号、数值、引脚标记和网络标签分角色。位号采用类别兼容性、距离、对齐和置信度做全局一对一匹配，允许型号与数值作为另外的字段绑定。前缀只作线索，不用Q、D等前缀强行覆盖器件类别。

输出：texts.json、component_records.json、binding_debug.json及叠加图。示例应能把U1与其型号、R1与10k、C1与100nF分别关联；不确定字段保留候选和原因。输出Name/value保留原始大小写、单位和字符；规范化文本仅用于候选检索，不静默改写赛事字符串。

位号正确绑定率=已绑定记录中位号和所属元件均正确的比例。真实位号覆盖率=正确恢复并绑定的真实位号数/参考中应恢复的位号总数。字段精确匹配率以所有应输出且参考已核验的字段为分母。未核验参考不参与正确率计算，另报覆盖范围。

## 2. 引脚定位、编号和名称

用户后续明确选择U-Net、不采用传统图像方法。当前方案与接口见 [U-Net导线与引脚方案](unet_wire_pin_plan.md)：tip由U-Net热图预测，编号与名称结合OCR关联；下文原先的模板路线保留为历史分析，不作为默认实现。

输入：原图、元件框/类别/身份、经核实的训练符号模板；IC分支使用局部引脚文字和取得后的正式元件库。

处理：先实现R/C/L等二端器件的方向与电气连接tip，再实现极性器件、MOSFET及IC。检测框可能包含引脚，不把bbox边界直接当tip；位置、编号和pinname分别恢复。不能用左右顺序猜所有器件的1/2，也不能把MOSFET的G/D/S或IC引脚排列随意套用。

输出：pin_candidates.json、pins预测、定位图；每个点保留所属元件、编号/名称候选及证据。

首轮验收：至少人工核验50个tip；在原图坐标5px容差下，已知模板的二端器件tip召回率目标≥90%；错误归属、漏pin和编号错误分别统计。编号和pinname另报严格匹配结果，不以位置接近替代编号正确。原始标注中的自动编号尚未获官方确认，不能将其作为全部真实物理编号的保证。

## 3. 导线提取与骨架拓扑

当前导线像素由U-Net预测，采用原分辨率切片与概率融合；原图颜色阈值/形态学分割不作为默认前端。分割后的线段和图关系转换仍需实现，交叉连接分类需要补充学习监督。草稿监督训练已完成，26 张去重图的导线像素 Dice 79.46%、IoU 65.92%；这些数据仍不是正式 Golden 或独立工程测试。

输入：原图、文字区域、器件主体区域和pin候选。

处理：先用颜色/二值化、形态学和线条分析建立可解释基线，再骨架化得到端点、分叉及路径。只屏蔽器件主体和文字，保留引脚引线；区分T连接、带连接点交叉和跨线不连接。断线补连使用线宽、方向及局部证据，不直接把评分5px容差当连线规则。规则法失败集明确后，再决定是否训练U-Net导线分割。

输出：wire_mask.png、skeleton.png、junctions.json、wire_segments.json及连接诊断图；每段使用原图坐标。

首轮验收：建立直线、折线、T形、交叉连接、跨线不连及断线样例；在已人工复核的局部图上检查误短路和漏连接。单独报告线段端点匹配F1（本地proxy、目标≥85%）与连接决策错误，不能用骨架像素IoU代替电气连接正确性。

## 4. 用NetworkX构建电气网络

输入：pin身份与tip、导线骨架图、连接点及网络标签。

处理：以引脚和线路节点建图，先求物理连通区域，再按已确认的标签与作用域规则合并逻辑网络。VCC/GND按赛题专门规则核验，不简单套用普通标签飞线。物理导线与逻辑标签连接分别保存，避免为了连通凭空画物理线段。

输出：nets，包含每个网的完整pin集合、hyperGraph和两点edges；保存pin到net的归属及每次合并原因。

首轮验收：悬空/不存在的pin引用为0；每个普通电气pin只能归属一个最终net；相似网名不能误合并。在经人工核验的小集上计算本地pin集合匹配F1，目标≥80%，并分别统计错合并和错拆分。正式NetHypergraphF1、NetLineF1需按官方匹配协议和评测器计算。

## 5. 完整JSON、联合评测与提交入口

输入：预测components、pins、nets及原图坐标信息。

输出：独立的赛事结构JSON和旁路调试文件。坐标只在出口转换一次；当前H-y仍是本地约定，需用正式Golden校准。未知字段不得靠同页参考JSON补齐。

验收：结构/引用/坐标校验通过率100%；重复键和越界为0；元件、引脚与网络实际预测非空且有覆盖报告；失败案例记录错误并计入评价范围。固定配置后测试完整入口、冷启动和总耗时。内部目标50例≤100分钟；赛题要求30–50例全部运行<2小时，最终以正式环境实测为准。

赛题准确度权重：ComponentF1 30%、PinF1 25%、NetHypergraphF1 35%、NetLineF1 10%；元件项还包含必要的身份/文本要求，并非YOLO类别+框F1。正式评测器未取得前，所有阶段指标明确标记为proxy或人工核验结果。
