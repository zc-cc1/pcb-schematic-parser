## 文件和基本结构

每例是原始 PNG 与配套 target JSON。训练文件实际常名为 `*_target_named.json`，Golden 常为 `*_target.json`，不要只匹配一种文件名后缀。

顶层固定为 `components`、`pins`、`nets`，三者都是对象。210 份文件中，元件记录字段均为 `Name/type/value/bbox`，引脚记录字段均为 `pinname/point`，网络记录字段均为 `hyperGraph/edges`。

| 部分 | 结构 | 需要保留的语义 |
| --- | --- | --- |
| components | `{元件key: {Name, type, value, bbox}}` | Name 大小写固定；value 可以是 null；bbox 为四数数组 |
| pins | `{元件key: {pin_后缀: {pinname, point}}}` | point 为 `{x, y}`；后缀是字符串身份，不保证为整数 |
| nets | `{网络key: {hyperGraph, edges}}` | 网络 key 不一定叫 net_N，也可以是 DM1 等标签 |
| hyperGraph | `"(元件key.引脚后缀,...)"` | 是字符串，引用 pin key 去掉 `pin_` 后的身份，不是 pinname |
| edges | `{edge_key: [{x,y},{x,y}]}` | 每条恰为两个点；折线拆成多条；不是一串完整路径点 |

## 实际例子：0005 的 DM1 网络

以下是原文件的完整 DM1 网络：

```json
{
  "DM1": {
    "hyperGraph": "(U2.2,U4.7)",
    "edges": {
      "edge_1": [{"x": 401.0, "y": 90.0}, {"x": 426.0, "y": 90.0}],
      "edge_2": [{"x": 429.0, "y": 90.0}, {"x": 403.0, "y": 90.0}],
      "edge_3": [{"x": 403.0, "y": 90.0}, {"x": 401.0, "y": 90.0}],
      "edge_4": [{"x": 46.0, "y": 230.0}, {"x": 69.0, "y": 230.0}],
      "edge_5": [{"x": 73.0, "y": 230.0}, {"x": 46.0, "y": 230.0}]
    }
  }
}
```

同一网络同时包含两个空间分开的可见分支，并有部分共线重叠线段。这表明网络的逻辑归属和图上连续路径是两个层次。不能为了让整个 net 在像素上连通而补画跨越空白区域的线；也不能未经评分口径核实就把所有重叠、共线分段合成一个长段。

## 坐标和身份约定

- README 只写“原始 PNG 图像坐标系”，没有明确原点。实图复核 0005 显示 y 向上、与左下坐标约定一致：图高 348，U4.pin_1 为 (73,292)，映射到图像左上坐标约 (73,56)，对应芯片左上第一根引脚。现有 H-y 出口与此样例方向一致；H-y 与 H-1-y 的一像素边界差异不能只凭 README 判为唯一官方规定。
- 保留浮点精度，图像缩放或切片后必须还原到原图坐标。坐标翻转只做一次。
- 引脚后缀不全是数字：Golden 有 `pin_FB`、`pin_TEMP`、`pin_19_1`；训练还有 `pin_EP` 及疑似文本混入的后缀。读取时不能强制转 int，也不能把这些样本都当作已确认无噪声的物理编号监督。
- 元件 key 与 Name 不恒等。训练中 IC 的 Name 经常是型号，Golden 的 box 记录则为位号。无位号器件还使用 `∅...` 等 key。
- type 使用数据本身的原字符串，如 `r/c/l/box/gnd/v`，以及 `battary` 等实际拼写；不能擅自改成自己认为规范的英文类别。
- 电源/地的 value 有多种字符串和 null，不统一填 GND/VCC。

## 数据版本与元件库

10 张 Golden PNG 与训练集中对应编号 PNG 全部字节一致，而 10 对 JSON 均不完全相同。这不是 210 张互不重叠的图片，也不能把这 10 张称为未见测试集。训练/验证划分应按图像内容去重；不同版本标注应分别记录，不直接混用。

cpntLibrary 是无扩展名的 JSON 文件，包含 337 个型号。其 pins 是多个同源符号实例的聚合，pin_id 不保证唯一，同一 number 也可能有不同 name；既有全量库检查发现 59 个型号存在编号到名称冲突。不能按数组位置分配物理引脚，也不能无条件覆盖图上名称。

## 对 U-Net 优化的直接意义

这份数据已经提供赛事结构的导线几何和引脚点，可直接从 nets.edges 生成导线监督、从 pins.point 生成 tip 热图，无需先绕回旧 CVJsonStd 转换关系。但它没有提供官方像素 mask 或统一线宽，栅格化宽度仍是训练约定。

评价时应分别检查原始线段覆盖、端点/转折点位置、引脚点定位及最终归网输出。像素 Dice/IoU 是辅助指标；整网在像素上完全连通不能作为所有线段是否成功表达的唯一条件。已有线上协议仍在匹配网络内评价 edge，因此最终输出也必须保留正确网络归属。

本次仅核对格式并保存说明，没有修改模型、训练数据、推理配置或提交包。
