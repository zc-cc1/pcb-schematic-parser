# 引脚定位与导线分析：实施前分析

> 方案已按用户后续要求改为U-Net，当前以 [U-Net导线与引脚方案](unet_wire_pin_plan.md) 为准。本文保留之前传统方法的分析记录，不再作为默认路线。

日期：2026-10-11。本文是方案分析；引脚与导线模块尚未实现，下列数字是建议的内部验收目标，并非实测或官方分数。

## 结论与当前基础

保持v3检测和semantic_v2文字模块冻结，先做传统图像处理、符号模板与OCR结合的基线，再按失败情况决定是否增加训练。引脚与导线需要相互校验，不能只按YOLO框四边或整图骨架端点生成引脚。

当前可直接复用原PNG、原图坐标detections.json、component_records.json、texts.json及OCR原始观测。运行环境已有OpenCV 4.12.0.88、NetworkX 3.7；scikit-image和Skan尚未安装。现有预测pins/nets为空；转换参考JSON含引脚和线路，但不是图片预测。

## 需要恢复的对象

引脚输出由所属元件、pin number、pinname和原图tip点组成。位置、身份和字符串分别评价。引脚tip是符号定义的电气接点，不一定在元件主体上，也不一定与YOLO框边重合。引脚引线与导线连续且无明显分界时，仅凭骨架不能唯一确定tip，需要符号模板/长度和尺度证据；证据不足时保留候选。

导线输出包括实际物理线段、端点、拐点、连接点及每条路径的归网关系。线路交叉的像素连通不直接等于电气连接。

## 引脚分支

第一批优先电容、电阻、电感：定位符号主体，判断水平/竖直/旋转，匹配已核验训练符号或允许的库模板，估计两侧电气接点，再检查线路方向和接触。几何上有两个候选点不能证明1/2编号；图上有编号时使用OCR，没有编号时按核验过的模板和官方转换约定处理。不能统一规定左=1、右=2。

IC分支先找实际矩形主体和每边进入的线路，再为这些连接位置组织局部OCR。pin number可能是P9/R8等字符编号，pinname可能是PLL_1V8/XTALN，须与器件位号和值区分。按同边位置、方向和对齐一对一关联，不按最近文字无约束分配。元件库或数据手册仅用于核验可见引脚及型号，不能把整封装的全部引脚补进本页符号。

晶振、极性电容、二极管、MOSFET、连接器和测试点分开处理。0002的X2图中有1/2/3/4四个接点，不适用二端晶振规则。Q1和TP7的现有类别错误应单独记入上游失败；不强行套错误类别模板。

## 导线与拓扑分支

1. 以原PNG处理，禁止把带蓝框、文字覆盖与诊断圈注的overlay当输入。灰度页和彩图分别建立候选；彩图中文字、符号和线条可能同色，颜色只能作为证据。
2. 文字去除使用保守的笔画区域与线路连续性检查。不能把整个OCR框直接涂白；否则可能剪断穿过框的线路。屏蔽元件主体时保留引脚引线与接触候选，不把整个YOLO框全部抹除。
3. 用scikit-image skeletonize细化前景；用Skan或自定义追踪生成像素路径。近邻度数只是节点候选，需把相邻分叉像素聚成节点，并检查原图上的点、T形、跨线桥和交叉形状。开源工具不提供电气连接语义。
4. 在端点、拐点、引脚tip、连接点切分为两点线段；保留原路径与切分原因。官方线段切分/归网仍需Golden核验。
5. 短断口补连同时检查方向、线宽、距离及原图连续证据，逐项记录补连。5px评分容差不是补线阈值；最近两条线不能直接吸附。
6. 图中有明确连接点时按局部线路证据连接；跨线桥保持两条通路；无点交叉按页内符号习惯和局部证据判断，无法判定时记为未决。不能用统一“无点必不连”覆盖所有样例。
7. NetworkX只处理已建立的正确图。不要因两个pin属于同一个电阻、电容或IC，就把它们之间加导线边；这样会把不同net错误短接。物理连通与同名标签逻辑合并分别保存。

## 先后顺序和评价

先用0002建立灰度电容与IC的可视化链路，再加入0001的R/C局部、0131的彩色R/C/L和水平/竖直样式。第一次只在已支持的器件分支上验证方法；不把未知分支当作零错误。

| 范围 | 建议首轮目标 | 必须另外报告 |
|---|---|---|
| tip定位 | 至少50个人工复核点；5px一对一匹配，精确率≥95%、召回率≥90% | 支持的类/模板范围、上游漏检、平均及95分位误差 |
| 编号与名称 | 在已核验的适用字段上严格匹配率≥85% | 位置对但编号/名称错、空字段、上游遗漏 |
| 线路几何 | 人工复核至少30个局部，覆盖直线/折线/T形/连接交叉/跨线不连/断口；线段端点proxy F1≥85% | 断线、误补线、切分口径、额外线段 |
| 电气拓扑 | 上述基础连接回归例中误短接为0；小集pin集合匹配proxy F1目标≥80% | 错合并和错拆分分别计数，未决交叉 |
| JSON | 所有导出的pin引用、线段结构、坐标及单网归属检查通过 | 仍为未知的组件身份/编号与未导出的对象 |

同时保留两种评价：用人工确认的上游输入诊断算法，以及用当前实际检测/OCR输出评价整体。后者须将漏检、错类别、错位号和空字段计入失败，不只统计成功绑定的引脚。

Dataset300转换参考含22409个本地自动编号、447个编号冲突及692条无可用路径的源导线待复核。这些数量不是模型错误率；不能直接把全部转换JSON作为可靠的引脚/拓扑训练真值。可以从中筛选并人工核验评价参考，正式图片推理不读取同页标注/CAD网表。

第一轮交付应是：一张tip编号图、一张导线骨架与交叉决策图、一张各net分色图，以及可追溯的逐项失败统计。定位错、编号错、线路断、交叉误连、上游失败必须可区分。

若规则法在核验小集上仍系统性漏掉特定引脚或无法分离同色文字线路，再考虑tip关键点热图模型或导线/连接点分割模型。新增训练需对应已核验标签和按工程划分的独立测试；当前没有理由直接宣称需要重训全部YOLO。
