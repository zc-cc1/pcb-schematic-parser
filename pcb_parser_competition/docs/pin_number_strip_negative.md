# 引脚编号窄带重识别：能读出来，但接进管道后没赚到（负结果）

日期：2026-10-18
结论：**识别本身成功（离线 8/8 全对），但集成后总分反而下降，已回退。**
当前部署状态：**69.62**（comp 0.843 / pin 0.826 / conn 0.558 / wire 0.415），13/13 成功。

## 1. 编号文字画在哪（这是本次要解决的前提）

EasyEDA 的引脚有两个文字属性：

| 属性 | 位置 | 对应输出字段 |
|---|---|---|
| Pin Name | 符号**内部**，贴内壁 | `pins[key].pinname` |
| **Pin Number** | 符号**外部/紧贴框外沿**，在该引脚**引线上方** | 拼成键名 `pin_<number>` |

实测（case 2 的 U1，4 个脚，框左沿 x=628，脚在 y=316/336/355/375）：四个引线上方**都有数字墨迹**，
但页级 OCR 只吐出一个 token（`3`，框在 x 618–628）。另外三个是 8px 小字、紧贴框线，没被切出来。

按“引脚外侧有没有墨迹”统计那 40 个没读到编号的引脚：**35 个有墨迹**（印了没读到），只有 5 个是真没印。

## 2. 窄带重识别怎么做（模块已保留）

`src/pcb_parser/pin_number_strip.py`：

- 取该引脚外侧、引线上方的窄带：沿引线 30px、向外 14px、**向上 9px / 向下 3px**
  （窗口必须窄，引脚间距约 20px，太高会读到隔壁脚的号）
- 放大 3×/4×/6× 后识别，只接受 `^\d{1,3}$`（或 BGA 球名 `^[A-Z]{1,2}\d{1,3}$`）
- 采纳条件：≥2 个视图一致；或单视图置信度 ≥0.99 且该号在该型号的库引脚集里
- 安全网：与同元件已有编号冲突则丢弃（否则导出会抛 `Duplicate physical pin key`）

配置：`configs/pin_number_strip_v1.json`

## 3. 离线验证：读得出来，而且对

在 case 2 / 1 / 11 / 13 上跑（用 20px 判定点和参考引脚对应）：

| 结果 | 数量 |
|---|---:|
| 读出并采纳 | 12 |
| **读对** | **8**（其余 4 个是 BGA 球名，我的判定脚本没覆盖） |

例：case 2 的 U1 读出 `1/2/4/1/1/4/1`，与参考 `1/2/3/4` 的对应位置**全部正确**。

## 4. 集成：两次撞硬约束，第三次才跑通，然后分数掉了

| 接入位置 | 结果 |
|---|---|
| `run_component_pin_library.py`（早期，位号未定型） | 崩：`Duplicate physical pin key in partial export` —— 后面的位号恢复会把两个元件合并成同一个 owner |
| `run_engineering_networks.py`（末期，导出前） | 崩：`Raw contact changed` —— 该阶段断言图的 `pin_attachments[].number` 与引脚一致 |
| 同上 + 把编号回写进 `graph['pin_attachments']` | **跑通 13/13**，但分数 **67.55**（低于 68.63） |

逐例对比（v28 有窄带 vs v23 无）：

| case | 变化 | 说明 |
|---|---:|---|
| 13 | **+10.8** | 元件 0.462 → 0.821 |
| 1 | **−6.8** | 元件 0.719 → 0.491 |
| 12 | **−6.7** | 元件 0.556 → 0.333 |
| 9 | −3.5 | 元件 0.824 → 0.706 |
| 2 / 3 / 4 / 10 | −1 ~ −4 | 元件小降 |
| **引脚项** | **0** | 一个引脚都没多拿到分 |

**关键：引脚分一点没涨。** 加了编号，但那些引脚仍然出不去——因为它们还缺另一项
（`pin_name_unresolved`），或者元件本身没被正确导出；而改动 `number` 反而让部分元件的导出集合变化。

## 5. 结论与下次怎么接

- 窄带识别这条路**技术上成立**（35 个里大半能读对），不做是无谓放弃；但**只在导出契约允许"补编号"时才有意义**。
- 下次要动，先做两步前置：
  1. 让 IC 的导出门槛接受"有编号、名字可用库/留空"（当前要求号+名齐全）；
  2. 把 `number` 的唯一真源放在一个阶段（现在就散在 `pins` 和 `graph.pin_attachments` 两处，
     任何补号都要同步回写，否则撞断言）。
- 装配位置建议放在 `apply_component_library` 内部（与消元填号同一处、同一份数据），
  而不是单独一个阶段。
