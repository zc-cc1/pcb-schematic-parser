## 3. 专门优化 YOLO，优先解决什么

### 优先一：用线上框检查口径评估定位

本次官方原始 summary 和逐例 protocol 的实际阈值是 **20 px**。需要保留常规 mAP，同时增加最终原图坐标下的中心误差、方向错误率、bbox 四坐标最大绝对误差，以及 20 px 通过率；5 px 可作为更严格的诊断项。原始 YOLO 框与最终导出框分别统计。

公开标注中 r/c/l/d/led 使用固定尺寸模板。例如电阻为 8×20 或 20×8，电容为 16×20 或 20×16。现有出口按预测中心和方向转换模板；IoU 较高不保证中心、方向和最终四坐标满足平台要求。IC 则没有一个通用模板，检测标注与实框范围需要单独核对。

第 13 图贡献了 18 个 bbox 失败中的 **9 个**，涉及电阻、电容、电感和 IC，最大坐标误差约 20.16～34.12 px。这种跨类别集中失配值得优先检查该图的缩放还原、坐标转换、中心定位和方向判断；现有证据不足以断言具体原因，也不能据此加全局平移。

### 优先二：拆清 20 个普通元件身份缺失

逐个关联“原图 → 原始 YOLO 框 → 切片/融合结果 → OCR 位号绑定 → 最终 JSON”。原始框阶段已缺失，才列为检测困难样本；框存在但 key 错误或没有导出，应在对应阶段修正。

真正漏检再按小目标尺寸、符号样式、拥挤程度、类别统计，决定补样本、调整采样或切片。不能从最终 JSON 缺失直接推出“统一降低置信度”或“所有类别再训更多轮”。阈值调整只在独立校准集选择；更换成 11s 时也不能照搬 v8n 的逐类阈值数值。

### 优先三：有证据后再做定向精修

目前匹配到的 192 个普通元件中仅 3 个 type 检查失败，且都集中在一张图。应先核对原始模型类别、类别映射、端口构造与文字绑定，确认是否为模型混淆。不能仅凭 BAT/LED+/LED- 这些 key 猜测正确类别。

对已经证实的模型问题，再整理一致的标注和困难样本，以 11s 为主线做一次受控精修；按原图/来源分组，避免切片或同图不同标注版本进入训练与验证两边。已有公开数据存在同一图像不同标注版本，须先统一评估目标。当前线上证据并不支持先延长轮数、继续扫学习率或换更大模型。

## 4. 如何判断 11s 对线上确实有帮助

先固定已验证的后处理、导出规则、运行时与输入，只比较探测器及在相同独立校准政策下取得的阈值；明确将其视为“探测器及校准策略”的比较。若还要单独归因网络权重，应另报预先固定阈值下的结果。

分别保存并比较：

- 原始/融合检测的逐类 P、R、F1、mAP 和定位误差；
- 平台口径下的完整元件 F1，以及检测、文字绑定、导出各阶段损失；
- 每图耗时、实际 device、显存和失败率。

线上这次实际使用 CPU、单进程，13/13 图成功，算法墙钟 925.112 秒，预算 1200 秒。11s 更换前需要实测完整管线耗时及实际 CUDA 可用性，不能只验证本机训练 GPU 可用。

第三次与第四次评测分别是 10 图和 13 图，输入及部分评分几何参考存在差异，不能把两次总分变化当作严格模型对照。若线上无法保证相同测试集与评分器，应在冻结的公开留出集上先做成对对照，线上结果作为补充证据。

## 5. 已修复但尚待线上确认的部分

截至已保存的最新上传说明，电源/地导出、LED 文字与几何、IC Name 选择和 IC 实框定位已进入新包；这些是后处理修复，检测权重没有改变，尚无该包的新官方分数。不要重复把这些修复算成后续 11s 训练的收益。

当前判断：继续使用 11s 作为探测器主线可以，但线上优化的首要依据应是**真实漏检清单和平台定位误差**。现有 28.92 分主要混合了导出、字段、引脚和网络等损失，不能用总分或元件综合 F1 直接诊断 YOLO 模型容量。
