# 官方资料文件夹的交叉核对：采纳了什么、纠正了什么

日期：2026-10-18
来源：`官方资料/`（Q&A 全文、三份库、`_derive/` 的派生分析）
结论：**有帮助，但主要价值是"校对规则 + 提供陷阱清单 + 现成工件"，不是新的分点。**
本轮采纳的改动让本地分从 54.82 涨到 **54.95**（pin 0.567 → 0.570）。

## 1. 直接采纳的三条

| 采纳 | 依据 | 实测影响 |
|---|---|---|
| **库保留全部别名**（不再把每个编号压成一个拼写） | `02` 第 2、5 节：`AMS1117-3.3` 的 1 号脚有 `GND/ADJ/GND\/ADJ/ADJ(GND)/ADJ\/GND/VSS\/ADJ` 六种写法，GT 用 `ADJ(GND)` | 13 页里有 **3 个引脚**因此拿到编号；pin 0.567 → 0.570 |
| **`Name != key` 守卫** | `02` 第 3 节：10GT 的 `Name` 是位号 `U1`，而库里真有一个 30 脚的元件叫 `U1`，直接查会假命中 | 本批数据不触发（open_GT 的 Name 是型号）；这是防止旧口径页面被绑错 30 个引脚的安全网 |
| **`_derive/check_conventions.py` 作为回归** | 5 项：坐标系、bbox 语义、type 白名单、库覆盖、假命中 | 当前数据 **5/5 通过** |

## 2. 他们已经做对、我这边也已经在做的

| 事项 | 出处 | 我的状态 |
|---|---|---|
| `∅` 电源符号必须导出（按坐标匹配） | Q&A 评测 #1/#4/#9；`04` 第 2 节 | 已导出（平台第 8 次评测 component 0.687 与本地一致，间接验证） |
| GND/VCC 同名合并成一个 net、编号不评分 | Q&A 评测 #4/#5/#6/#9 | 连通性里已按电源轨合并 |
| 非 box 元件的 pinname/pinnumber 不计分 | Q&A 评测 #2/#6 | 评分器与出口都按 IC-only |
| 元件按 key 匹配、bbox 不参与匹配、20px 只用于命中后 | PDF p7、p17 注 b | 与平台第 8 次逐例逐位相同，已验证 |
| bbox 是本体框、引脚 tip 在框外（中位 20px） | `03` 第 4 节 | 与我的 pin tip 外推结论一致（tip 在线端） |
| 不要把库编号里的 `_1/_2` 原样写出 | `02` 第 4 节 | 已做 `canonical_number` 归一 |
| 不要用几何顺序猜 box 编号 | `02` 第 5 节 | 我的实现只按"名字→编号"和"观测到的编号保留"，没有几何猜号 |

## 3. 被这次评测结果覆盖的旧结论

| 旧说法（10GT 时代） | 现在 |
|---|---|
| "库被位号卡住，pin TP 只有 4，修好位号能到 58，PinF1 .076 → .730" | 第 8 次评测 pin F1 **0.574**，本地 88 个命中——这条路已经走通 |
| "别在库的准确度上花力气（88% 到顶）" | 那个 88% 是"型号已知时"的数字；现实是 34 个 IC 只认出 17 个。模糊型号 + 引脚名模式又赚了 +0.75 |
| "连通/线段 45% 权重长期接近 0" | 第 8 次：连通 0.480、线段 0.315 |

## 4. 还有两条没实现的官方规则

| 规则 | 出处 | 现状 |
|---|---|---|
| 一个引脚多编号（`"5,6,7,8,9"`）拆成 `pin_5…pin_9` | PDF p18 注 d | 未实现。本批数据不触发：我们的 447 个 pin key 与 GT 的 pin key 全是单编号，没有逗号/斜杠 |
| `type_list`（34 类）白名单 | Q&A 一般 #3/#4/#14/#17 | 官方未发布；目前用 open_GT ∪ 10GT 的 21 类当白名单 |

## 5. 建议向官方索取（`01` 第 9 节也这么写）

1. **`type_list`**：唯一还缺的官方文件，决定 type 是否有判错风险。
2. **官方评测代码**：PDF p8 注 e 承诺过"会提供评测代码与完整边界说明"，至今未见。
3. **`∅` 元件的坐标匹配规则**：第 8 次评测的事实支持它（我们导出后 component 与平台口径一致），但书面确认仍然值得。
