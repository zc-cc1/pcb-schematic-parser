## 2. 官方口径是从平台自己的报告里读出来的

`评测结果/第二次评测/scoring_result/report/submission/*/1.json` 里有一段 `protocol`，逐条抄录：

| 项 | 官方原文 |
|---|---|
| 元件 | `ordinary: key/type/Name/value exact; power: type/value and one-to-one geometry, ignore key/Name; ordered bbox, every coordinate within threshold` |
| 引脚 | `component key and pin_<number> exact; owner exists in both components; pinname exact; point Euclidean threshold` |
| 引脚范围 | **`IC only`**（GT 已知 key 用 GT 类型；只在预测里出现的 IC 引脚算 FP） |
| 连通 | `merge nets sharing global power rails, then Hungarian one-to-one mixed-vertex-set soft F1` |
| 电源轨 | 所有地共享 GND；电源按 value（空→VCC）；地与电源分开 |
| 权重 | .30 / .25 / .35 / .10 |

这纠正了我们本地三处实现假设：

1. **电源符号不吃 key**（按 type+value+几何一对一配对）。之前按 key 匹配，把 134 个匿名电源符号全记成 FP，component F1 被压到 0.462。
2. **PinF1 只算 IC**。被动/符号引脚两边都不计分。
3. **连通是软 F1**（Hungarian 一对一 + 顶点集 F1），不是"引脚集合完全相等"。

`scripts/platform_metrics.py` 按上面的文字实现；在本次 13 例上与平台第 7 次评测的 component
（0.7108）相差 0.004，connectivity（0.0330）相差 0.005，可以当标尺用。

> 注意：`src/pcb_parser/contest_metrics.py` 在本次评测期间被并发改写（两次编辑到一半就报
> `NameError: anonymous_components`），所以口径固定在 `scripts/platform_metrics.py`，不依赖它。

## 4. 引脚为什么只有 0.031

口径是 IC-only：GT 有 191 个 IC 引脚，我们只导出 67 个（覆盖 35%），其中 4 个全对。

| case | GT IC 引脚 | 我们导出 | 命中 |
|---|---:|---:|---:|
| 1 | 40 | 6 | 0 |
| 2 | 16 | 7 | 0 |
| 4 | 12 | 6 | 0 |
| 7 | 5 | 3 | 3 |
| 12 | 9 | 0 | 0 |

按旧口径（不计电源、不限于 IC）的逐引脚归因：GT 692 引脚里 tp 6、owner_unmatched 297、
**no_pin_exported 205**、number_absent 65、point_far 119。也就是说 IC 引脚**根本没被导出**，
而不是导出后算错。部署链的出口仍在要求"元件位号 + 引脚号 + 引脚名"三者齐全，三者缺一就扣。

## 5. 元件侧：0.706 的预算

| 结果 | 数量 | 说明 |
|---|---:|---|
| ok | 155 | 普通元件按 key 命中 |
| key_absent | 154 | 其中 **134 是匿名电源符号 `∅<n>`**——官方按几何配，这部分在 0.706 里已由几何配对补回 |
| bbox_far | 25 | 被动元件盒子：GT 跨符号含引脚（如 23×58），我们写 8×20/16×20；r 中位偏差 16.8px、p90 24.3 |
| text_diff | 9 | box/ic 的 Name、r/c 的 value |
| type_diff | 3 | |

两条**不能凭直觉改**的结论（都已测过）：

1. **box 的 Name 应该写型号，不是位号**：26 个可比的 box 里，GT Name 等于型号的 20 个、等于位号的 6 个；
   把 Name 改成位号，component F1 0.462→0.402（旧口径实测）。
2. **不要为了"去假阳性"删掉匿名元件**：旧口径下删掉 `UNRESOLVED_DET_*` 涨 0.113，但官方口径下
   gnd/v 按几何配对，删掉等于把 82 个已命中的电源符号扔掉。

## 7. 试过但回退：按页自适应的被动元件框

想法：参考里同一个被动件在不同页画成 23×58 / 40×16，固定 8×20 只能贴合一种约定；检测框本身
跟着图形走，所以用"检测框 × k"代替固定表。

离线扫描（用 v8 的产物 + 原始检测框）看起来很好：

| k | 1.0 | 0.9 | 0.8 | 0.7 | 0.6 | 0.5 |
|---|---:|---:|---:|---:|---:|---:|
| open_GT component | 0.709 | 0.715 | 0.727 | 0.727 | 0.727 | 0.727 |
| 10-Golden component | 0.240 | 0.240 | 0.240 | **0.256** | 0.256 | 0.256 |

但端到端接进去（`PCB_BBOX_SCALE_PASSIVE=0.7`）反而 **0.706 → 0.695**，总分 53.45 → 53.09。
原因：管线在那一层拿到的框是**融合后的检测框**，不是离线扫描用的原始检测框，所以 0.7 缩得过头。
已把该开关默认设为 0（关闭），代码与注释保留，记录这个负结果。
