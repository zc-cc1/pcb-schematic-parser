# 引脚编号与名称阶段 v1

本阶段在 U-Net 引脚坐标、YOLO 元件框和引脚归属关系之后，使用 RapidOCR 的 PP-OCRv6 检测/识别模型读取图片文字。编号与名称由独立的文字证据产生，几何关联只决定文字属于哪个已预测引脚。

## 输入与输出

- 输入：PNG，以及现有 YOLO/SAHI、U-Net 和 RapidOCR 权重；支持使用图片哈希校验过的归属/OCR 预测缓存。
- 输出：`pin_text_result.json`、`pin_text_overlay.png`、`texts.json`、`component_records.json`、两类绑定调试 JSON、`summary.json`。
- 每个引脚保留原图坐标、元件归属、编号与名称、字段状态、文字位置/置信度/来源、备选读法与全局分配稳定性。
- 图片模型入口不读取参考标注、转换参考 JSON、CAD、SPICE 或离线评估文件。没有新增训练，没有按位置排序猜编号。
- 引脚编号可来自可见数字或 IC/连接器的球位字符串，例如 `12`、`R8`、`U18`。大小写和文字拼写保持 OCR 原文。
- 名称主要覆盖有内部文字的 IC、连接器、运放与 block。外部网络标签不直接充当引脚名称；其他符号没有可靠名称证据时保持 null。

## 绑定与复读策略

1. 从 PNG 做现有整图/分块/旋转 OCR，用冻结的元件文字绑定模块恢复元件身份。
2. 根据引脚所属框的最近方向构建文字候选区域，按同侧引脚间距限制绑定范围。此步骤不改变 U-Net 点坐标。
3. 分别选择编号、名称。已用于元件位号/型号/数值的文字不能再作为引脚字段。
4. 空间上同一组文字采用一对一全局分配；读法冲突、共享文字、同器件重复编号、同一文字的编号/名称角色歧义均保留未决。
5. 实验开关下，缺字段的引脚附近做 RGB 裁剪放大和 0/90 度 OCR。触及裁剪边界的读法保留在拒绝日志中，避免截断词变成假名称。
6. 局部复读不会重新分配已经冻结的元件身份。全部引脚候选保留，不因编号缺失而删除候选。

单页局部裁剪上限为 64，每个裁剪最多两个方向。达到预算的剩余候选记录在 `skipped_by_ROI_budget`；这不算成功恢复。ONNX OCR 使用 CPU 4 线程，YOLO 与 U-Net 支持 GPU。运行日志记录实际 OCR 模型文件哈希。

默认采用整图/分块 OCR 绑定。局部复读实验使名称联合 F1 从 58.46% 降到 57.78%，虽然编号正确数增加 3 个，本轮没有将它设为默认。实验结果单独保存在 `runs/s6_pin_text_v1/local_experiment`。

## 运行

在桌面“新建文件夹”中的项目根目录运行：

```powershell
.\scripts\run_pin_text.ps1 -Image 'data/standardized/0002/0002.png' -Device 'cuda:0'
```

这条命令从 PNG 运行检测、分割、归属和文字阶段，默认输出到 `runs/pin_text_predictions/0002`。可用 `-Output` 指定目录，用 `-Device cpu` 跑 CPU。

调试固定的上游结果：

```powershell
.\.venv-gpu\Scripts\python.exe scripts/run_pin_text.py --image data/standardized/0002/0002.png --ownership runs/s5_pin_ownership_v1/0002/pin_ownership.json --output runs/pin_text_debug/0002
```

可追加 `--texts` 使用现有模型 OCR 缓存。默认关闭局部复读，可追加 `--enable-local`，或在 PowerShell 入口追加 `-LocalOCR`，显式运行该实验。外部缓存的来源配置和文件哈希记录在结果中，不把外部缓存运行与全新 OCR 运行混称为同一条件。

固定 26 页的纯预测批处理入口为 `scripts/batch_pin_text.py`。`scripts/evaluate_pin_text.py` 只用于离线参考评估，与 PNG 入口分开；它不被推理脚本导入。结果和复核队列见 `runs/s6_pin_text_v1/report.md`、`evaluation.json`、`text_review_queue.json`。

在转移后的目录复算已同步的离线结果，使用导出的草稿参考快照：

```powershell
.\.venv-gpu\Scripts\python.exe scripts/evaluate_pin_text.py --reuse-references
```

参考快照带图片哈希，只能用于离线评估，不应传给推理入口或直接加入训练集。

## 指标与限制

- 文字恢复数量：分别计编号、名称及两者都有的候选，不把数量当作正确率。
- 条件字段精确率：仅在元件归属及坐标已匹配、参考有字段的引脚上，计算正确字段/输出字段。
- 条件字段覆盖率：在同一可评分范围内，计算正确字段/应输出字段；缺字段计入分母。
- 非空名称的联合代理指标：同时要求类别/框匹配、元件归属正确、点误差≤5px和名称严格匹配；不含编号，不能代替正式 PinF1。
- 图像核对小样本：沿用已核对的 0002 页 14 个编号与 8 个名称，单独要求位号/归属/坐标/文字匹配；不扩大为全数据集真值。

26 张图仍是已有开发验证数据。源标注缺失编号和部分实际引脚，多数字段未经完整人工认证。源空编号/自动编号不当作实际物理编号评分。v1 尚不支持多编号 pad 拆分，不保证所有符号的编号/名称恢复。带单元后缀的元件位号（例如 U1H）仍可能未决。

当前结果是带证据的中间预测。编号、名称未决项、无元件归属候选及疑似源标注缺失进入复核队列；训练标签不自动更改。正式 pins/nets 导出尚未完成。

下一阶段从 U-Net 的导线概率建立图拓扑，并处理交叉连接、跨线不连接和文字网络标签。NetworkX 负责电气图的表示和连通关系，不替代导线/结点的识别模型。
