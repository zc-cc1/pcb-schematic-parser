# 引脚与元件关联 v1

本阶段把 U-Net v2 的引脚候选点关联到冻结 YOLO v3 检出的元件。它是关系构建阶段，不重新检测引脚，不移动 tip 到框边，不猜引脚编号。

## 输入、输出与边界

- 输入：PNG、已有 YOLO/SAHI 与 U-Net 权重和配置；可选使用带图片哈希的模型预测缓存及已有 OCR 元件身份记录。
- 输出：`pin_ownership.json`、`ownership_overlay.png`、检测/引脚预测缓存、运行摘要。直接运行模型时还保存 U-Net 概率图与导线 mask。
- 每个引脚保留候选 ID、原图坐标、置信度、元件归属、排序后的归属候选、距离/代价和未决原因。
- 状态包含：已分配、多个元件归属相近、附近无元件、落在大型器件内部、器件角点待核验。全部候选保留。
- 导线概率仅作为上下文诊断，低导线概率不会删掉可能悬空的真实引脚。
- 仅在已有 OCR 元件身份缓存与检测索引/框匹配时，把 DET ID 关联到 IC2、R7 等身份。引脚 `number`、`pinname` 保留 null，等待文字证据。
- 推理入口不读取源标注、同页参考 JSON、CAD 或 SPICE 文件。没有原图颜色阈值、形态学或霍夫分割。

## 固定 26 页实测

沿用 13 张开发图/13 张保留验收图，配置在本轮首次评估前固定，没有继续按验收页调参。它们仍是参与过模型开发的旧验证页，不是独立工程测试。评估参考为未经完整人工认证的草稿。

| 项目 | 结果 |
|---|---:|
| 全部引脚候选 | 1477 |
| 有明确元件归属 | 1268 |
| 附近无元件 | 128 |
| 归属歧义 | 60 |
| 位于大型器件内部，待复核 | 21 |
| 原始引脚坐标 F1 | 70.17% |
| 已分配候选的坐标 F1 | 67.84% |
| 元件归属与坐标同时正确的联合 F1 | 65.12% |
| 已定位且已分配候选的归属一致性 | 95.99% |
| 正确归属且定位的覆盖率，相对原坐标 TP | 86.34% |

联合指标要求元件类别相同且 bbox IoU≥0.5，并要求引脚所属元件正确及坐标误差≤5px；不评价编号和名称，因此不是正式 PinF1。归属一致性的分母仅为已定位且已分配候选，不代表所有引脚的准确率。

仅按是否有归属删除候选会使坐标 F1 从 70.17% 降到 67.84%，所以没有采用这种硬过滤。原始候选与未决记录完整保存，下游可分别处理。

坐标匹配诊断中，906 个位置正确且归属一致，87 个位置正确但归属未决，58 个位置正确但对应参考元件未通过检测框/类别匹配，3 个位置正确但归属不同。重合标注引脚可能让坐标匹配产生歧义，以联合最大匹配为主要计分。

`runs/s5_pin_ownership_v1/label_review_queue.json` 包含 423 条复核建议，涉及 tip 定义、位置偏移、未标注引脚或假预测；没有自动修改标注或 `approved_cases`。

## 运行

在项目根目录：

```powershell
.\scripts\run_pin_ownership.ps1 -Image 'data/standardized/0002/0002.png' -Device 'cuda:0'
```

默认从 PNG 运行 YOLO+SAHI 和 U-Net，再建立归属关系。可以用 `-Output` 指定输出目录。CPU 同样支持：

```powershell
.\scripts\run_pin_ownership.ps1 -Image 'C:\path\schematic.png' -Device 'cpu' -Output 'runs/ownership_new_image'
```

Python 入口还支持 `--detections`、`--pin-predictions`、`--component-records`，用于固定上游结果调试。缓存必须满足图片 SHA256、尺寸、坐标系、模型/配置指纹约束；OCR 身份缓存还检查检测索引与框是否一致。

检测入口默认使用单独的 `configs/pin_ownership_detector_v3.json`，内容冻结为已采用的 v3 权重、分类阈值和融合设置，不依赖训练目录是否包含 `baseline_v3_adopted.json`。该配置只服务于本阶段推理，不改变现有 YOLO 训练配置；模型权重哈希不一致时会停止运行。

## 下一阶段

1. 按复核队列核对 tip/base 和未标注引脚，并完善未决归属处理。
2. 对已归属引脚做局部 OCR，恢复编号与名称；不按坐标排序臆造编号。
3. 从 U-Net 导线预测建立拓扑，增加交叉连接/跨线不连接的监督和判断，再用 NetworkX 建立电气网络。
4. 编号、名称、网络和坐标出口验证完成后，输出正式 components/pins/nets JSON。当前关系文件是调试产物，不能作为完整比赛答案。
