# 放宽网络出口：连通 0.476 → 0.576，总分 62.85 → 66.39

日期：2026-10-18
改动：
- `src/pcb_parser/wire_graph_artifacts.py` 新增 `PCB_NET_EXPORT_POLICY`（默认 `loose`）
- `src/pcb_parser/whole_network_export.py` 的出口守卫同步放宽
- 新增 `PCB_NET_ALLOW_GAPS`（默认 `1`）
- `scripts/run_pin_output_rules.py` 的复核卡片对"无归属引脚"做了防崩溃处理

## 1. 为什么该放宽

连通指标是**每条网络的软 F1**（`2×交集 / (预测成员数 + 参考成员数)`），
然后把所有网络的成员汇总成 tp/fp/fn。所以：

> 一条 5 个成员的网络，我们只凑出 2 个 → 这条网络得 `2×2/(2+5) = 0.57`；
> 而整条扣掉 → 得 **0**。

原来的出口在三种情况下整条丢弃：
`只剩一个成员`、`路口（T 型连接）没解析`、`怀疑断线`。这三类合起来占了被扣网络的
55%，而它们丢掉的分远大于多出来的假成员。

## 2. 改了什么

| 策略 | 行为 |
|---|---|
| `strict` | 原来的全部硬门（≥2 成员、路口必须解析、不许断线） |
| `partial` | 允许成员身份不全（≥2 成员） |
| **`loose`（默认）** | **只要有 ≥1 个可解析成员就导出**；路口、单成员不再拦 |
| `PCB_NET_ALLOW_GAPS=1`（默认） | 断线候选网络也导出 |

保留的硬门只剩：**一个成员都解析不出来**（空网络）和自环。

## 3. 实测（13 页，平台口径）

| 版本 | 连通 F1 | tp / fp / fn | 总分 |
|---|---:|---|---:|
| 旧出口 | 0.476 | 210 / 10 / 452 | 62.85 |
| **放宽（loose）** | **0.569** | 292 / 72 / 370 | **66.08** |
| 放宽 + 允许断线 | **0.576** | 300 / 79 / 362 | **66.39** |

精度从 0.955 掉到 0.792，召回从 0.317 升到 0.441——**F1 净赚 0.10**。

## 4. 一个副作用（已修）

放宽后有些网络带"无归属引脚"，复核卡片渲染时 `cmap[None]` 直接崩（case 8 整个失败）。
`run_pin_output_rules.render_network_cards` 已改成跳过没有 owner 的成员。

## 5. 剩余空间

放宽后：tp 300 / fp 79 / fn 362。参考 231 条网络里，我们仍只有约 130 条能凑出 ≥2 个成员，
其中 81 条只能凑出 1 个成员、20 条一个都没有——**这些是身份缺失**（引脚 66 个、元件 key 32 个），
不是出口问题。

## 6. 回退

```powershell
$env:PCB_NET_EXPORT_POLICY='strict'   # 回到最初的硬门
$env:PCB_NET_ALLOW_GAPS='0'           # 只保留出口放宽、不导出断线
```
