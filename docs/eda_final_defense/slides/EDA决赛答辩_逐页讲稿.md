## P3 Part I · 解题思路(40 秒)

**问题是什么?** 赛题给一张原理图 PNG,要输出 components、pins、nets 三段 JSON。大家第一反应是"检测 + OCR"。但我们的判断写在最上面:**难的不是找到符号,而是恢复电气连接**(The Hard Part Is Not Finding Symbols. It's Recovering Connectivity.)。

**方法是什么?** 整个系统一条主线:**Perceive 识别**元件文字引脚导线 → **Connect 建立几何与拓扑** → **Verify 用证据修复校准**。中间的示意条就是输出结构:Components、Pins、Nets **靠同一个共享 Component ID 关联**,最终生成 Target JSON——这就是四个官方难点各自对策的落点:密集检测用双路 YOLO 加 WBF 融合;引脚归属用双头 U-Net 热图加代价指派;文字关联用多视角 OCR 证据门控;拓扑连通用保守建图加事务式修复。

**结果如何?** 检测 F1 0.883,后面每一步都有量化验证。

> 记忆卡:**难在恢复连接,不在找到符号;Components/Pins/Nets 靠共享 Component ID 串成 JSON。**

## P4 Part II · 系统架构(30 秒)

**问题**:这条流水线环节很多,怎么让评委快速看懂?

**方法**:把 11 个阶段压缩成四层——**Visual Perception** 视觉感知(YOLO 双路、双头 U-Net、离线 OCR)→ **Geometric Processing** 几何处理(引脚归属、骨架线段、框校准)→ **Connectivity Reasoning** 连接推理(物理网、飞线与电源合并、字段补全)→ **Evidence-Gated Correction** 证据门控修正(事务式修复、官方格式校准、JSON 导出)。

**结果**:每层职责单一、可独立验证;11 阶段完整版在备份页 A。全程零 LLM Token、逐阶段哈希锁定与审计日志。

> 记忆卡:**四层:感知 → 几何 → 连接推理 → 证据修正;细节在备份页 A。**

## P5 视觉感知(40 秒)

**问题**:一张图里元件、引脚、导线、文字全混在一起,怎么可靠地"看清"?

**方法**:按本页从左到右的流讲——**Schematic PNG** 进来,三个默认开启的模型各管一件事:**YOLO nano** 整图+SAHI 切片双路,WBF 按置信度融合,给出元件边界框(右侧第一行真实输出,35 类);**PP-OCRv6** 多视角 OCR,给出文字、位置、置信度(第二行的 SW1 真实裁切:型号 PTS8153JK250SMTRLFS,置信度 0.998,双视角);**双头 U-Net** 共享特征,一个头出导线掩膜、一个头出引脚热图(第三行两个小图)——解码出 **431 个引脚候选:287 assigned · 115 ambiguous · 29 unowned**。

**结果**:检测 F1 0.883(59 例)。模型来源如实(左下):YOLO 与 U-Net 自研训练(U-Net 用开源 milesial 实现做基础结构),PP-OCRv6 调用开源、离线运行;**JunctionCNN 虽然训练了,但默认管线关闭**,只作可选增强。

> 记忆卡:**PNG → 三模型 → 证据下行;候选非结论;JunctionCNN 默认关。**

## P6 拓扑重建(45 秒)

**问题**:权重 0.35 的网络超图,最难的是 T 型十字、断线、飞线——连错了比漏连扣分更狠。

**方法**:主图就是**真实局部预测叠加图**(官方示例页 U3 区域,导线按网络着色)。右边三步对应图上 1/2/3 三个标记:**① Pin ownership**——把每个解码端点匹配到元件边界与引脚方向,431 个候选里 287 个确定归属;**② Wire tracing**——在工作掩膜里追踪端点、拐点、结点之间的线段,T 型十字一律保守拆分、断线只记录不乱接、恢复必须有硬证据;**③ Net membership**——共享支撑路径的端点归入同一网络并保留走线几何,同名飞线标签做逻辑合并,VCC/GND 要过四道门才合并电源网。

**结果**:下方数字——**238 个物理网络候选、362 条边,这是建图阶段的中间表示;经过飞线和电源合并,最终输出 63 个逻辑网络**。页 13 案例 F1 从 58.72% 提到 85.19%(下一页)。

> 记忆卡:**归属→追踪→成网;238 候选是中间态,最终 63 个逻辑网。**

## P7 核心亮点:Repair Without Guessing(80 秒,重点页)

**问题**:模型输出永远有噪声,怎么在不猜的前提下把结果修到能拿分?

**方法**:这页只讲一件事——页 13 的导线结点归并,全程"不猜"。左边是真实裁切:两条绿色导线交叉处的红色结点就是实测证据。合并必须满足两条硬证据之一:两条线段同一直线重合超过 60 像素(角度差 3 度内、垂距 2 像素内),或两端逼近同一个实测红点且沿途墨迹支持率超过 95%。合并只动网络成员和边,元件引脚一个不动,每页最多 8 组。

**结果**:修复前导线 32 对 28 错 17 漏,F1 58.72%;修复后 46 对 13 错 3 漏,**F1 85.19%,连通 67.14% → 87.53%,单页总分 82.871 → 92.656**。其余 12 页逐字节不变——这是单页开发集消融,不是官方整体指标。归因说明:这个提升来自结点归并机制本身;SW1/SW2 那类多视角 OCR 型号恢复是另一项独立能力,在备份页 E。

> 记忆卡:**页13 结点归并:32/28/17→46/13/3,58.72%→85.19%(单页消融);F1 提升归因于归并机制本身。**

## P8 输出校准(40 秒)

**问题**:识别对了,如果写得不符合官方约定照样丢分——评分是像素级硬指标。

**方法一:端口方向规则(右上)**。原理图里的红色旗形端口符号带方向:我们读它的**五边形轮廓和唯一电气端子**——端子在尖端一侧是输入(net_input),端子在尖端对侧就是输出;导线接入位置就是那个紫色端子点。落到 Target JSON:`"type": "net_output"`、`"Name": "VOUT"` 保留说明文字、`"value": null`。这条规则只在轮廓与单一端子证据一致时才生效,否则字段原样保留——最终代码里实现并有 14 项单元测试(4 种旋转 × 2 种镜像)覆盖。旧口径是 net_bidirection,旧提交可用环境变量切换回去。

**方法二:统计校准(左列)**。类型与字段规范:resistor 映射成 r,145 个匹配元件验证;Name==key 约定来自 9186 个组件统计,box 保留芯片型号。bbox 校准:canonical 约定在 40 页公开子集把 20px 达标率从 0.905 提到 1.000;按页缩放在 13 页把达标元件从 150 提到 159——**两套口径独立成立,不能相乘**。引脚尖端 18px 吸附加 1000 型号引脚库。

**结果**:左下——官方示例页上,U3 边界框与官方标注只差 **1~2 像素**(官方容差 20px)。

> 记忆卡:**端口方向=端子与尖端相对关系,证据不足不动;两套 bbox 口径独立;U3 差 1~2px。**

## P12 Part IV · 总结与展望(40 秒)

**左栏:What the system delivers——三项技术贡献**:一是 **Pin-to-net reconstruction**,元件边界、引脚位置与导线路径共同决定哪些引脚同网,只在硬证据上合并;二是 **Traceable Target export**,Component ID 与 pin ID 把每条属性、每个网络成员、每段走线都拉回到原图;三是 **Score-aware output calibration**,bbox 规范、Name==key、引脚库映射全部对齐官方标注统计。如实说明(左下斜体):**JunctionCNN 已训练但默认管线关闭**,只是可选增强,不是默认推理骨干。

**右栏:Future development——后续验证方向**:一,独立评估——留出全新来源的图纸测跨源泛化;二,密集引脚与交叉走线——审计漏检引脚与伪结点;三,结点模型与数据增长——验证后把已训练结点 CNN 转正,扩充难例与跨域数据。

**底部一行:工程能力说明**——Docker 镜像 pcb-parser:v102 交付、SHA256 清单、逐阶段审计日志、626+ 单元测试、零 LLM Token。我们的目标始终是——让每一条导线都有证据。谢谢评委。

> 记忆卡:**左三贡献右三展望,底一条工程能力;JunctionCNN 默认关如实讲。**
